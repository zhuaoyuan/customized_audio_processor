# 使用说明：10 分钟跑通第一个文件

> 面向第一次使用本项目的人。所有命令都在项目根目录 `C:\projects\local\audio_processer` 的
> **PowerShell（pwsh）** 下执行，按顺序复制即可。
>
> **最短路径**：§2 的「90 秒切片」约 **30 秒** 就能得到 8 件产物；§3 的完整单文件（100 min）约 **13 分钟**。
> 进一步的时间/磁盘/成本数字见 [`docs/运行评估.md`](运行评估.md)。

## 2. 快速路径：90 秒切片最小验收（约 30 秒）

### 2.1 从 `data/` 切一段 90 秒

```powershell
ffmpeg -v error -ss 600 -t 90 -i "data\24_【复旦哲学系丁耘】 亚里士多德《形而上学》(01)_normal..m4a" -c copy -y work\demo_90s.m4a
```

预期：`work\demo_90s.m4a` 约 **680,128 B / 90.004 s**。可校验：

```powershell
ffprobe -v error -show_entries format=duration,size -of default=noprint_wrappers=1 work\demo_90s.m4a
```

### 2.2 跑全链路

```powershell
work\venv\Scripts\python -m app.cli run "work\demo_90s.m4a" --out out_demo --cache-dir work\cache_demo
```

> `--out out_demo` 会把产物、`jobs.db`、日志都放到 `out_demo/`，不污染主库 `out/`。

预期输出（阶段行随指标变化，下面是示例）：

## 3. 完整单文件（100 min，约 13 分钟）

```powershell
work\venv\Scripts\python -m app.cli run "data\24_【复旦哲学系丁耘】 亚里士多德《形而上学》(01)_normal..m4a" --out out --cache-dir work\cache
```

- 首次跑要建缓存，会比后面跑同一个 job 慢；之后 `run` 同一 job 会 **按产物跳过**（默认续跑）。
- 单文件请**直接 `run`，不要先 `scan`**（见 §6.6）。
- 常用开关：
  - `--force`：已有产物也重跑（仍复用 decode/analyze 缓存）；
  - `--keep-intermediates`：保留中间 wav（默认清理，节省磁盘）；
  - `--json`：stdout 纯 JSON，便于脚本/Agent 调用；
  - `--preset fast|standard|quality`：参数预设（默认 `standard`）。
- 预期：`[OK] <job_id> clean=xx.xmin segs=xxxx chars=xxxxx artifacts=8/8 ...`，
  `out/<job_id>/` 下 8 件产物；100 min 文件约 **12.8 min**（RTF 0.1282，见 `docs/运行评估.md`）。
  跑过 `finalize` 后 `clean.m4a` 移到 `output/audio/`（见 §3.2）。

查看已有任务：

```powershell
work\venv\Scripts\python -m app.cli status
```

## 3.1 可选：全文成稿（`compose`）

转写稿是逐句 ASR 输出，段短、口头禅多、专名按段孤解。`compose` 把**整讲**通读成课程档案
（结构大纲 + 术语表），再分块整理为书面讲稿（段首保留 `[mm:ss]`，为 **clean 音轨** 时间，
对齐 `clean.m4a`；原始音频时间见 `manuscript.json` 的 `orig_time`）：

```powershell
# 先看分块方案（不调用 API、不花钱）
work\venv\Scripts\python -m app.cli compose 0a7fa0ed_复旦哲学系丁耘_亚里士多德_物理学_05 --dry-run

# 真正成稿（需要 DEEPSEEK_API_KEY；约 ¥0.6/讲，1h43m 讲座串行约 14 min）
work\venv\Scripts\python -m app.cli compose 0a7fa0ed_复旦哲学系丁耘_亚里士多德_物理学_05
```

- 产物：`manuscript.md`（成稿）、`manuscript.json`、`compose_card.json`、`compose_report.json`；
- 默认按 transcript 内容 hash 跳过已完成；`--force` 重做，`--no-cache` 忽略分块缓存，
  `--chunk-chars 1800` 调块大小；默认串行（1,800 字/块，1h43m 约 14 min），
  网关配额允许时可用 `--concurrency 2/4` 加速（实测 4 路长请求容易被排队或超时）；
- 失败块只会回退为「机械去语气词」，不会阻塞整篇；成稿**未逐字校对**，引文/页码请对照原音；
- `compose` **不在** `run` 全链路里（避免批量时成本失控），需要单独调用。
- 推理强度可配：默认 `correct.reasoning_effort=low`、`compose.reasoning_effort=high`、
  `compose.analyze_reasoning_effort=high`（可选 `none/low/high/max`）；实测依据见
  [`docs/推理强度调研与实测.md`](推理强度调研与实测.md)。

## 3.2 可选：交付目录整理（`finalize`）

`batch` / `compose` 跑完后可选执行一次，把「要交付的」按原始文件名集中到产物根的 `output/`：

```powershell
# 先看计划（只打印，不移动/不改名、不改盘）
work\venv\Scripts\python -m app.cli finalize --out out --dry-run

# 真正整理（幂等，可重复执行）
work\venv\Scripts\python -m app.cli finalize --out out

# 机器可读结果
work\venv\Scripts\python -m app.cli finalize --out out --json
```

整理后的典型布局（以 `out/1` 为例；其中 14 个 job 已迁移）：

```
out/1/
  output/audio/【复旦哲学系丁耘】 亚里士多德《物理学》(05-20100401)_5_normal..m4a
  output/manuscript/【复旦哲学系丁耘】 亚里士多德《物理学》(05-20100401)_5_normal.md
  dc97800d_【复旦哲学系丁耘】 亚里士多德《物理学》(04下-20100325)_4_normal/
    report.json / transcript.* / manuscript.md / …（clean.m4a 已移走）
  jobs.db  logs/
```

它做四件事：

1. **重命名 job 目录**：`<hash8>_<原始文件名主体>`（名字取自该目录 `report.json` 的 `source`）。
   不再按 20 字截断，`(04下-20100325)` / `(08上)` / `(08下)` 这类同名不同讲能区分开；
2. **集中成品音频**：`clean.m4a` → `<产物根>/output/audio/<源原始文件名>`（含扩展名，不保留冗余副本）；
3. **集中成稿**：`manuscript.md` 复制到 `<产物根>/output/manuscript/<原始文件名主体>.md`，
   job 目录里的原稿保留；
4. **同步索引**：`report.json`（`id` + 新增 `delivery` 段）、`manuscript.json` /
   `compose_report.json` 的 job_id/path、`jobs.db` 的 jobs/stages id 一起更新。

注意：

- **幂等**：重复执行只补缺失/更新，不会改乱已整理好的目录；`--dry-run` 只打印计划、不改盘；
- **与重跑的关系**：`run` / `batch` 重跑仍写回原 job 目录（按产物跳过/续跑），整理过的目录跑完可
  再执行一次 `finalize` 补齐；`status` / `retry` 用的 `jobs.db` id 已同步，不受影响；
- **Web UI 不受影响**：服务端 `/api/jobs/{id}/audio` 会回退到 `output/audio`，播放 / 改字 / 导出照旧；
- **先看计划再执行**：`clean.m4a` 是移动不是复制，job 目录改名后旧 id / 旧路径不再存在；
  `run_abc.ps1` 已在 A+B+C 之后自动执行 finalize。

## 5. Web UI（只在本机 `127.0.0.1`，无鉴权）

### 5.1 启动

方式 A：双击根目录 **`start_web.bat`**（自动设 UTF-8、`cd` 到项目根、`serve --port 7860`）。

方式 B：命令行启动：

```powershell
work\venv\Scripts\python -m app.cli serve --port 7860
```

想用刚才的 90 s 演示库：

```powershell
work\venv\Scripts\python -m app.cli serve --port 7860 --out out_demo
```

预期输出（默认 `--out out`）：

```
Web UI: http://127.0.0.1:7860
数据库：...\out\jobs.db
上传目录：...\out\uploads
Ctrl-C 退出
```

若加了 `--out out_demo`，后两行会变成 `...\out_demo\jobs.db` / `...\out_demo\uploads`
（`--out` 同时把 db/logs/uploads 落到该目录）。

健康检查（本机实测）：

```powershell
Invoke-WebRequest -Uri "http://127.0.0.1:7860/api/health" -UseBasicParsing
# HTTP 200，内容：{"ok":true,"version":"0.2.1"}
```

浏览器打开 **<http://127.0.0.1:7860>**。

### 5.2 页面操作

1. **登记任务**：顶部输入本地目录（默认 `data/`）→ 点「扫描登记」；或点「上传音频…」，
   文件保存到 `out/uploads/` 并登记（不写 `data/`）。
2. 左侧任务列表点选任务（状态色 / 阶段 / 耗时），顶部汇总 pending/running/done/failed。
3. 详情页：播放 `clean.m4a`（服务端支持 Range，可拖动）、点「开始处理」/「重试」、
   看阶段与产物。
4. 转写表格：每页 100 行，点时间（如 `[12:34]`）跳转播放；「原文」（`text_raw`）只读，
   改「修正」列（`text`）后点「保存修改」→ 写回 `transcript.json` 并重新导出 md/srt/txt。
5. 下载 md / srt / txt。
6. 进度通过 SSE（`GET /api/events`）实时刷新，断线自动重连。

> **安全**：服务只监听 `127.0.0.1`，**没有登录/鉴权**。不要改 `--host 0.0.0.0`，不要把端口转发到公网。

## 6. 常见问题（FAQ）

### 6.1 没有 DEEPSEEK_API_KEY 会怎样？

不会失败。`correct` 阶段自动 `enabled=false`，写一个空的 `corrections.json`，`report.correct`
仍是完整对象，其余 7 件产物照常产出。本轮 6 文件验收就是在**无 key** 状态下完成的（纠错成本 ¥0）。

### 6.2 怎么设置 DEEPSEEK_API_KEY？

三种方式，任选其一：

```powershell
# A) 只对当前终端有效
$env:DEEPSEEK_API_KEY='sk-你的key'

# B) 设为当前用户环境变量（重开终端后生效；注意会明文存在用户环境里）
[Environment]::SetEnvironmentVariable('DEEPSEEK_API_KEY','sk-你的key','User')
```

```powershell
# C) 放本地私有文件（.gitignore 已忽略 work/set_key.ps1）
#    文件内容一行：$env:DEEPSEEK_API_KEY = 'sk-你的key'
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass   # 默认策略会拦未签名脚本
. .\work\set_key.ps1
```

- 不要把 key 写进 `configs/default.yaml`（已入库，会泄露）；含 key 的文件一律不要提交。
- 确认生效（不打印 key 明文）：

  ```powershell
  work\venv\Scripts\python -c "from app.config import load_config; from app.pipeline.correct import resolve_api_key; print('key_loaded=', bool(resolve_api_key(load_config())))"
  ```

- **真实 API 实测（2026-10-22，P9 修复后）**：连通/鉴权/7 块并发都正常，f24 全量 7 块 ≈79 s、
  **≈¥0.379/文件**（P5 估算 ¥0.112 的 3.4 倍）；真实输出现在能安全写回——f24 产生 **202 处修正
  / 164 段**，0 整块回退，121 段因边界标点重分配保守回退原文（`segment_rejections`）。详见
  `docs/工程日志.md` P9 节与 `docs/运行评估.md` §6.4。首次接真实 API 建议先跑 1 个文件，
  看 `corrections.json.rejected_chunks` / `segment_rejections` 与 `report.correct.cost_cny`。
- **`compose`（全文成稿）也要 key**：无 key 时 `correct` 会静默降级，但 `compose` 会直接报
  「缺少 API key」；它按讲单独计费（实测 1h43m ≈¥0.58–0.61（档案冷启动约 ¥0.60）），批量前先用 `--dry-run` 看分块数。

### 6.3 中文文件名 / 空格 / 括号会有问题吗？

实测可用（`data/` 下 6 个样例文件名都含中文，部分含空格、括号、书名号）。注意：

- 路径**一定加引号**：`run "data\24_【复旦哲学系丁耘】 ..._normal..m4a"`；
- 控制台保持 UTF-8：先 `$env:PYTHONIOENCODING='utf-8'`（`start_web.bat` 已 `chcp 65001`）；
- 超长路径（>260 字符）未验证。

### 6.4 模型缺失（`config check` 显示 `[MISS]`）

把模型放到 §1.3 表格的默认路径，或设置 `MODEL_DIR` 指向模型根目录（其下仍按同样子目录组织）：

```powershell
$env:MODEL_DIR='D:\models'   # 例如 D:\models\sensevoice\model.int8.onnx
work\venv\Scripts\python -m app.cli config check
```

模型缺失时 ASR 阶段会失败：`status` 里看到 `job failed @ asr`，`stages` 有失败行；补齐模型后
`work\venv\Scripts\python -m app.cli retry <job_id>` 从失败阶段续跑。

### 6.5 端口 7860 被占用

```powershell
Get-NetTCPConnection -LocalPort 7860 -State Listen | Select-Object LocalAddress,LocalPort,OwningProcess
```

换端口：

```powershell
work\venv\Scripts\python -m app.cli serve --port 7861
```

若确认占用进程是自己之前的服务，可 `Stop-Process -Id <上一步的 OwningProcess>`（**先确认不是别的程序**）。

### 6.6 先 `scan` 再 `run` 同一个文件，会多出一个 pending 任务（真实坑）

`scan` 记录的是**相对路径**，`run` 会按**绝对路径**重新登记，因此同一个文件可能生成两个 job
（一个 pending、一个 done）。本机实测 `out_demo` 里就有一个多余的 `..._demo_90s` pending。
**不影响产物**，只是任务列表多一行。正确用法：

- **单文件**：直接 `run <文件>`（自动登记）；
- **目录**：`scan <目录>` → `batch <目录> --resume`；
- 若已产生重复 pending：不影响运行，可忽略；想清干净就删掉自建的产物目录重来（**不要删 `out/` 里的真实验收产物**）。

### 6.7 Web 页面能打开、但播放/改字没反应？

- 确认服务还在运行（终端窗口不要关），`GET /api/health` 返回 200；
- 改字时该 job 正在跑会返回 **409**（跑完再改）；
- 单段 `text` 上限 5000 字，上传单文件上限 2 GB；
- 2 小时级 `clean.m4a` 首次定位可能要等浏览器缓冲；建议 Chrome/Edge，Safari 未验证。

### 6.8 `work/cache` 占了几 GB，能删吗？

`work/cache` 是中间 wav + analyze/decode 缓存（本机当前约 **4,854 MiB**，见 `docs/运行评估.md` §4）。
编排器成功后会自动删 `clean16k.wav`，但 `16k.wav` 保留用于分析缓存/续跑。可以手动清：

```powershell
# 安全：只删 clean16k 与 44.1k 中间 wav（保留 16k / analyze.json / decode.json）
Get-ChildItem work\cache -Filter *.clean16k.wav | Remove-Item
Get-ChildItem work\cache -Filter *.44k.wav | Remove-Item
```

注意：**不要删 `*.analyze.json`**；删 `*.16k.wav` 会让 analyze 缓存失效（每个文件重算约 48 s，
见 `docs/运行评估.md` §3），只在磁盘紧张时做。批量 500 h 若全量保留 16k 缓存会到 ≈107 GiB，
必须按任务/按队列清理。

### 6.9 在 Web 里改字会改动 `transcript.json` 的换行风格吗？

**P8 起已保留原换行风格**：服务端原子写沿用原文件换行——原文件是 CRLF 就仍写 CRLF、是 LF 就仍写 LF
（文件不存在时才用 LF），**不再把 CRLF 规范成 LF**。JSON 内容不变，md/srt/txt 不受影响；
如需严格字节级对照，改前先备份 `transcript.json`。

### 6.10 批量时能开多个进程吗？

不能。默认单进程（`batch.jobs=1`），`--jobs` 参数保留但只支持 1——P3 实测进程池并行比单进程
8 线程**慢 22%**；ASR 是单例 8 线程，并发跑两个 pipeline 只会互相拖慢。
