## 1. 目标与验收（一句话）

输入 `data/*.m4a`（乱命名、含空格、可能有损坏容器）→ 输出 `out/<id>/`：
**干净音频（降噪+裁剪+响度归一）+ 带句级时间戳与发言人的转写稿（LLM 按主题修错字）+ 可核对的明细**；
支持 300+ 文件批量、断点续跑、Web UI 与 CLI；单文件（100 min）≤15 min；跨文件语音电平极差 ≤1.0 dB。

## 2. 技术决策（已锁定，不再讨论）

| 项 | 锁定值 | 依据 |
|---|---|---|
| 目标语音电平 T | **−20.0 dBFS ASL**（语音帧能量均值） | 广播级常用；实测 6 文件可达成（报告 §5） |
| 跨文件容差 | 归一化后 ASL 与 T 偏差 **≤ ±0.5 dB** | 需求③ |
| 文件内波动 | 5 min 窗口 ASL 的 p5–p95 **≤ ±1.5 dB**（超限才启用慢变增益） | 需求③ |
| 增益策略 | **默认 V1+V2**：每文件静态增益归一到 T，再叠加受控慢变（窗 20 s、hop 5 s、clamp ±3 dB、速率 ≤1.5 dB/s、20 ms 交叉淡化）；源内波动 >6 dB 的文件单独放宽 clamp 到 ±6 dB。实测 6/6 触发，V2 后窗口半展宽 0.26–1.44 dB | 实测 §5.4 |
| 按说话人增益 V3 | **默认关闭**；仅在 diarization 可信（≥2 个稳定说话人、每簇 ≥30 s、主簇占比 <90%）时启用 | 实测单说话人时 diarization 裂成 27 簇，V3 会引入 ±5 dB 跳变 |
| limiter | 真峰值 ≤ **−1.0 dBTP**；增益上限 **+24 dB**。**必须用真峰值限幅**（4× 过采样测真峰 → 下调 ceiling 重做，ceiling −2.5～−3.0 dBFS）：样本峰限幅实测 +0.8 dBTP，修复后 5/6 达标，f00 残 −0.90 | 实测 §5.4 |
| 降噪 | `highpass=f=80,afftdn=nr=12:nf=-30:tn=1` @44.1 kHz；低 SNR 文件（SNR<12 dB）可升到 nr=16 | 报告 §3 |
| 裁剪 | 头尾：首/末个"讲课段"边界（见下）；内部：VAD 非语音 ≥3 s 切除，两侧留 0.25 s | 需求② |
| 讲课段判定 | **120 s 窗口**聚合：`chars/s ≥ 2.0` 连续 2 个窗口 → 讲课；头尾各最多扫 15 min（可扩到 30 min）；边界留 0.5 s | f24 实测：0–480 s 窗口 cps 0.24–0.47，480–600 s 跳到 2.26；尾部 4560 s 后 1.49。VAD/段级判据都会被音乐骗过 |
| 内部长静音 | ≥3 s 的 VAD 静音段切除；**碎片语音（<3 s）默认保留**（保守） | 需求②④ |
| 无关人声 | 默认**全部保留**；只删：①头尾非讲课 ②非主讲说话人 ≥5 s 且 ASR 字符率 <0.5 ③VAD 语音但 ASR 空。删除明细写入 `edit.json.removed_reasons` | 需求④"保守" |
| 转写 | VAD 段逐段 ASR（段长 0.5–30 s，过长按 30 s 切），句级 start/end；**禁止字符比例估时间** | 报告 §7 |
| 发言人 | 默认只标 `主讲`（单说话人）；仅当 diar 抽样（10 min）发现稳定第二人（≥5 s 且 ≥3% 语音）才全量 diar | 全量 diar RTF 0.083，300 文件要 41 h |
| LLM 纠错 | deepseek-flash，分块 2,000–2,500 字，严格约束；diff ≤12%、数字/句数校验，超限回退；输出 `corrections.json` | 报告 §8 |
| 输出音频 | `clean.m4a`：44.1 kHz mono AAC 96 kbps（源 <44.1k 则升到 44.1k） | 兼容性好、体积小 |
| 并发 | 单进程；ASR 8 线程；`--jobs` 仅用于 I/O 重叠，默认 1 | 实测进程池慢 22% |
| 模型 | sherpa-onnx：Silero VAD（faster-whisper 自带 onnx）+ SenseVoiceSmall int8 +（可选）pyannote-segmentation/cam++ diar | 全部 CPU、宽松许可 |

- 验收：`scan` 后 `status` 显示 6 个 pending。

### P2 分析：VAD / 电平 / 边界（1 天）

**P2-T1 VAD**
- 写作用域：`app/pipeline/analyze.py`
- 要点：Silero VAD ONNX（从 faster-whisper 包内取，或 `sherpa_onnx.VoiceActivityDetector`）；参数：threshold 0.5、min_speech 250 ms、min_silence 300 ms、pad 100 ms；输出 speech segments + 10 ms 帧级语音标记。
- 验收：6 文件 speech_ratio 落在 0.60–0.90；与 `work/scan/vad/*.json` 的段数差异 <10%。

**P2-T2 电平与窗口统计**
- 写作用域：`app/pipeline/analyze.py`
- 要点：只统计"≥3 s 连续 VAD 段"内的语音帧 → `asl_dbfs`、p10/p50/p90、noise_floor（最安静 10% 帧）、SNR；5 min 窗口 ASL 的 p5/p95/spread；EBU R128 用 ffmpeg `ebur128` 解析作对照。
- 验收：`python -m app.cli analyze <id>` 输出与报告 §2 表格数值偏差 <1 dB（同一文件）。

**P2-T3 头尾边界判定（关键，已在 f24 上验证算法）**
- 写作用域：`app/pipeline/analyze.py`
- 要点（**按 120 s 窗口聚合，不要按段判**——段级判据会被音乐上的短幻觉词骗过）：
  1. 对头/尾各最多 15 min 区域，按 VAD 段逐段送 SenseVoice（复用 P4-T1 封装）；
  2. 以 **120 s 窗口**聚合：`chars_per_sec = Σ非标点字符 / 窗口时长`、`speech_ratio = VAD 语音秒数 / 窗口时长`；
  3. **讲课窗口** = `chars_per_sec ≥ 2.0`；从起点连续 2 个讲课窗口 → head 边界 = 第一个讲课窗口起点；尾部反向同理（实测 f24：0–480 s 窗口 cps 0.24–0.47，480–600 s 跳到 2.26，600 s 后稳定 3.7–4.3；尾部 4560 s 后降到 1.49）；
  4. 若 15 min 内未找到 → 扩到 30 min；仍无 → head=0 并 flag `head_uncertain`；
  5. 边界两侧各留 0.5 s 余量，避免切掉第一个字。
- 验收：
  - f24 head = 480 s ±30 s（**不得**落在 3.6 s 或 59 s 这类 VAD/段级误判点）；
  - f06 / f20 head ≈121 s（需人工听 10 s 确认是前奏还是讲课）；f05 head ≈0–10 s；
  - 6 文件边界写入 `report.json.trim`，并与人工抽听 5 个边界一致。

**P2-T4 内部长静音列表**
- 写作用域：`app/pipeline/analyze.py`
- 要点：VAD 非语音段 ≥3 s 记为候选切除；标记是否在 head/tail 之外。
- 验收：f24 内部长静音总时长 ≈613 s（±10%），最长段 ≈170 s。

### P3 音频渲染：降噪 + 裁剪 + 响度（2 天）

**P3-T1 降噪**
- 写作用域：`app/pipeline/denoise.py`
- 要点：ffmpeg 滤镜字符串封装；`arnndn` 需 `cd` 到模型目录用相对路径（Windows 冒号坑）；输出 44.1k float wav 临时文件。
- 验收：对 f24 前 10 min 处理，语音段 ASL 变化 ≤1 dB，非语音段 RMS 下降 ≥3 dB，耗时 ≤5 s/10 min。

**P3-T2 裁剪与映射**
- 写作用域：`app/pipeline/trim.py`、`tests/test_trim.py`
- 要点：按 head/tail 边界 + 内部长静音（两侧留 0.25 s）生成 kept 区间；输出 clean 44.1k 临时 wav（ffmpeg `aselect`/`atrim` 拼接或 numpy 切片）；生成 `edit.json.kept/removed`；提供 `orig_to_clean(t)` / `clean_to_orig(t)` 工具。
- 验收：映射往返误差 <1 ms；f24 clean 时长 ≈3412 s（±3%）；语音段交集保留率 100%。

**P3-T3 响度归一化**
- 写作用域：`app/pipeline/loudness.py`、`tests/test_loudness.py`
- 要点：
  - 在 clean 16k 上按 P2-T2 口径算 `asl_in`；
  - **基础增益（V1）**：`gain = T - asl_in`，clamp 到 [−24, +24]；
  - **默认叠加 V2 慢变**：每 5 s 控制点（20 s 窗）算窗口 ASL，目标增益相对静态增益 clamp ±3 dB、变化率 ≤1.5 dB/s；控制点间线性插值，整段 20 ms 交叉淡化（实测 6/6 触发，V2 后窗口半展宽 0.26–1.44 dB；wlx 源内 8.25 dB，clamp 放宽到 ±6）；
  - 在 44.1k 上施加增益（numpy 向量化，禁止逐样本 python 循环）；
  - **true-peak limiter**：真峰值 ≤−1 dBTP。实现：oversample×4 检测峰 + 软限幅，或 ffmpeg `alimiter=limit=-2.5dB` 后再用 `ebur128` 验证；**注意 PoC 的样本峰限幅实测只到 +0.8 dBTP，不可接受**；
  - 重新测量输出 ASL，必要时迭代一次（最多 3 次）。
- 验收：`tests/test_loudness.py` 用合成正弦/噪声断言增益数学、clamp、插值、限幅；真实文件：输出 ASL 与 T 偏差 ≤0.5 dB、**ebur128 真峰值 ≤−1 dBTP（硬断言）**、削波样本 0、最长增益变化率 ≤1.5 dB/s。

**P3-T4 输出音频**
- 写作用域：`app/pipeline/export.py`
- 要点：44.1k float → AAC 96 k mono m4a（`-c:a aac -b:a 96k`）；同时写 `edit.json.gain` 与 `report.json.levels`。
- 验收：`ffprobe` 验证 44100/mono/96k；体积 ≈43 MB/小时；播放器可播。

**P3-T5 六文件批量渲染 + 跨文件校验**
- 写作用域：`app/tools/regress.py`
- 要点：对 6 文件跑 P1–P3，输出 `work/regress/audio.csv`：in/out ASL、LUFS、真峰值、裁剪比例、耗时。
- 验收：**6 文件 out ASL 极差 ≤1.0 dB（实测已达 0.05 dB）**、**全部 ebur128 真峰值 ≤−1 dBTP**、无削波、单文件总耗时 ≤15 min。

### P4 转写：分段 ASR + 时间戳（2 天）

**P4-T1 SenseVoice 封装**
- 写作用域：`app/pipeline/asr.py`
- 要点：`Transcriber(model_dir, threads=8)`；`transcribe_segment(float32[16k]) -> text`；支持批量段（顺序 decode，复用 recognizer）；`text` 用 `use_itn=True`。缓存 recognizer 单例（加载 ~1–3 s，勿每段重建）。
- 验收：对 60 s 样本转写，文本与 `work/bench/asr_sv_t4.json` 一致（字符相似度 >0.98）。

**P4-T2 分段转写与时间戳**
- 写作用域：`app/pipeline/asr.py`
- 要点：输入 clean 16k + VAD 段（clean 时间轴）；段长 >30 s 均分；逐段转写；丢弃纯标点/空段但保留时间；结果按 clean 时间排序；`trim.py` 提供 orig 时间映射写回 `transcript.json`。
- 验收：f24 总段数 900±100、字数 15,000–17,500、`n_empty` 比例 <5%；**时间戳误差中位 ≤0.5 s、P90 ≤1.5 s**（对 10 min 样本用 faster-whisper 词级时间戳作参照，脚本 `app/tools/measure.py`）。

**P4-T3 说话人（可选）**
- 写作用域：`app/pipeline/diarize.py`
- 要点：默认 `method=none` → 所有段 `speaker="主讲"`；`sampled` 模式：取正文 3 个 5 min 片段跑 sherpa diar（threshold 0.7），若发现≥2 个 ≥5 s 且 ≥3% 语音的说话人 → 全量 diar（threshold 0.7）并把最长者标 `主讲`，其余 `其他1/2`；否则保持单标签。**绝不臆造发言人。**
- 验收：f24 抽样判定 `n=1`（全标主讲）；对已确认有多人的文件（`work/scan/diar/f00` 显示 9 个簇/主 72%）跑全量，标签数 ≥2 且 `其他` 总时长与抽样估计同量级（±50%）。

### P5 纠错与导出（2 天）

**P5-T1 DeepSeek 纠错客户端**
- 写作用域：`app/pipeline/correct.py`
- 要点：OpenAI 兼容接口 `https://api.deepseek.com/v1/chat/completions`，model=`deepseek-flash`；`DEEPSEEK_API_KEY` 从环境变量读，缺失则 `enabled=False` 并写 warn（不阻塞流水线）；重试（429/5xx，指数退避，最多 3 次）；超时 120 s；并发 ≤8。
- 验收：无 key 时流水线跳过纠错；有 key（或 mock server）时 1 块文本往返成功。

**P5-T2 分块与提示词**
- 写作用域：`configs/prompts/correct_system.txt`、`app/pipeline/correct.py`
- 要点：按句边界 2,000–2,500 字分块；system prompt 固定（便于前缀缓存）；user 内容 = 课程主题 + 热词表 + 待改文本；输出仅正文。参照报告 §8.1 的约束与示例。
- 验收：对 `work/cost/correct_test/input_chunk1.txt` 跑一遍，输出与 `corrected_chunk1.txt` 的修正点重合率 ≥70%（人工/脚本对比）。

**P5-T3 校验与回退**
- 写作用域：`app/pipeline/correct.py`、`tests/test_correct.py`
- 要点：diff 率 = 编辑距离/原长；数字与书名号数量不变；句数变化 ≤5%；不满足 → 该块回退原文并记 `rejected_chunks`；写 `corrections.json`（含 items）。
- 验收：构造超限改写样例被拒绝；正常样例通过。

**P5-T4 导出**
- 写作用域：`app/pipeline/export.py`
- 要点：`transcript.md`（[mm:ss] 发言人：文本）、`transcript.srt`（clean 时间轴，带发言人前缀，SRT 时间格式）、`transcript.txt`、`corrections.json`、`report.json`。
- 验收：SRT 可被 VLC 正确加载（用 ffprobe/格式断言）；md 时间与 srt 一致。

## 7. 已知坑（必须规避，均来自本机实测）

| # | 坑 | 规避 |
|---|---|---|
| 1 | `ffmpeg arnndn` 不接受 `C:` 绝对路径（filter 冒号解析） | `cd` 到模型目录，用相对路径 `m=sh.rnnn` |
| 2 | huggingface_hub 走 hf-xet 在 Windows 报 `OSError: I/O error 拒绝访问` | `HF_HUB_DISABLE_XET=1` + `HF_HOME=<可写>` + `HF_ENDPOINT=https://hf-mirror.com` |
| 3 | PyPI `sherpa-onnx` wheel 是 CPU-only，`provider="cuda"` 静默回退 | 不要指望 GPU；如需 GPU 用 faster-whisper(CT2) |
| 4 | 进程池并行比单进程 8 线程慢 22% | 默认单进程；`--jobs` 只做 I/O 重叠 |
| 5 | MP4 `stco` 偏移损坏（1/6 样例）导致 AAC 解码报 "Reserved bit set" | P1-T1 修复；修不好进 quarantine |
| 6 | Silero VAD 把片头音乐/掌声判为语音 | 头尾边界必须 ASR 字符率复核（P2-T3） |
| 7 | 单说话人时 sherpa diar 会裂成几十簇 | 默认不做 per-speaker 增益；抽样确认≥2 人才启用 |
| 8 | numpy 逐样本施加增益极慢 | 向量化 + 控制点插值；目标 RTF <0.02 |
| 9 | 32 kHz 源 / 双声道同源 | 统一 16k 分析、44.1k 输出；downmix 单声道 |
| 10 | 中文输出乱码 | 所有脚本 `PYTHONIOENCODING=utf-8`，文件读写显式 `encoding='utf-8'` |
| 11 | 长音频 ASR 幻觉 | VAD 分段逐段解码，不整段喂入 |
| 12 | 文件名含中文/空格/括号 | 全程用 `Path` 对象与列表参数调用 subprocess（不用 shell 字符串拼接） |
