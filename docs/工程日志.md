关键实现与踩到的真实问题：

- **stco 修复算法（P1-T1）**：解析 box 树 → 收集**非空** `stco` 表 → `delta = mdat_payload − min(offset)` → 全部偏移统一平移 → 另存副本（**源文件只读**，字节不变）。加固点：
  - 候选 delta **先试 0**（最常见情形），再试「各 mdat payload − 各表最小偏移」，第一个通过 `validate_alignment` 的候选即采用；修补后再自检（重解析 + delta=0 复验：全部偏移落在某个 mdat 内、单调不减），**自检失败就报错而不是写出坏文件**；
  - 支持多 track（音视频）与多 mdat；`stco` 条目数为 0 的空表**跳过而不是报错**；
  - `co64` 明确报「不支持」；非 ISO BMFF 返回 `applicable=False`；`dst == src` 拒绝。
- **真实样例的关键发现（计划外）**：`data/` 里 **5/6 是 fragmented MP4（`moof`+`trun`，moov 中 `stco` 表为空）**，只有 `f00` 是普通 MP4 且 `stco` 偏移整体小 22118 B。修复器必须先识别「有 `moof` 且无有效 stco → 无需修复」（`note` 字段说明），否则会把正常文件误判为损坏。已用 `test_real_samples_have_no_offset_damage` 锁住该行为。
- **解码（P1-T2）**：`ffprobe` 探测 → `ffmpeg -map 0:a:0 -ac 1 -ar 16000 -c:a pcm_f32le` → **校验产物时长**（不只看返回码：损坏容器可能 exit=0 但产出空文件）→ 失败则修复容器重试 → 仍失败则 `ok=False` + 明确 error。缓存 `<id>.16k.wav` + `<id>.decode.json`（源 size/mtime + wav 字节数 + 时长三重校验），命中时不调用 ffmpeg。
- **float32 决策被实测锁死**：`f04` 的 16k float32 解码后 `max|x| = 1.77`，有 **1,047,930** 个样本 > 1.0；若先转 int16 削顶，后续真峰值/限幅判断全部失真。已写成回归测试 `test_decode_real_f04_keeps_overshoot`。
- **id 规则（P1-T3）**：`<文件名 sha1 前 8 位>_<可读短名>`，短名保留中日韩与 ASCII 字母数字、按 token 边界截到 20 字符、丢弃 `normal/copy/mp4…` 噪声词；同名不同目录用全路径 hash 4 位消歧。实测 id 例：`621cb91c_0_20140227_丁耘_西方哲学`、`7927721f_24_复旦哲学系丁耘_亚里士多德`。

关键实现与**口径校准**（先做实验再定逻辑）：

- **ASL 口径**：调研报告 §2.2 的表格用的是「全部 VAD 段、帧功率简单平均」（`asl_all_vad_dbfs`），而计划 §1.2 锁定的定义是「**≥3 s 连续段**、帧功率简单平均」（`asl_in_dbfs`，正式口径）。实测两者差 0.0–0.8 dB；另保留 P.56（`rel_db=15`）口径 `asl_p56_dbfs` 供 P3 响度使用。三点都写进 `levels`，避免后人再猜。
- **VAD 与 PoC 完全一致**：复用 faster-whisper 内置 Silero v6（threshold 0.5 / min_speech 250 ms / min_silence 300 ms / pad 100 ms）。实测 6 文件的 `n_segments` 与 `work/scan/vad/*.json` **逐个完全相同**（1057 / 2367 / 1360 / 1723 / 1732 / 1291），内部非语音总时长也一致到 0.1 s。
- **头尾边界（按计划，但改了两个关键细节）**：
  1. 窗口内字符**用「≤30 s 分块转写」而不是「只送 VAD 语音段」**。实测 f24 的 480–600 s 窗口：只送 VAD 段（覆盖 38 s）得 206 字、cps **1.72**（<2.0 → 头边界错到 599.5 s）；整窗 30 s 分块转写得 270 字、cps **2.25**（与报告 §2.3 的 2.26 一致 → 头边界 479.5 s ✓）。原因是 VAD 漏掉与音乐/回声重叠的讲课声，而分块转写能捞回来——音乐段字符率仍极低（0–120 s cps 0.03），不会误判。
  2. 「连续 2 窗口」加**软窗口**规则（`1.0 ≤ cps < 2.0` 允许夹 1 个）：f06 的 120–240 s 是正常讲课（cps 2.97），240–360 s 掉到 1.82（轻声/停顿）；严格连续会把头边界跳到 359.5 s、白切 240 s 讲课。头部起点还允许**向前吸收 1 个软窗口**（f00 的 0–120 s 课前寒暄 cps 1.81），片尾终点允许**向后延伸 1 个软窗口**（收尾常是轻声），两头都按「宁可留着」处理。
- **内部长静音两种口径分开记**：`total_s` = 语音段之间的空隙总和（与报告 §2.3 对齐）；`cut_s` = 头尾裁剪区之外、P3 真正要内部切除的量；另记 `in_head_tail_s` 避免 P3 重复计数。
- **缓存**：`work/cache/<id>.analyze.json`（含 VAD 段表、窗口表、长静音候选），带 `ANALYZE_VERSION` + 关键参数指纹，算法一改自动失效（本轮因口径变化两次 bump：2→3→4）。

数据流（`python -m app.cli render <id|--all>`，也可由 `app.tools.regress` 直接调 `render_job`）：

```
decode(need_44k) → analyze(缓存) → denoise(44.1k) → trim(clean44k + edit 映射)
→ loudness(V1+V2 + 真峰值限幅 + ASL 校正迭代) → encode AAC 96k
→ 回读 m4a 真峰值/ASL（不达标下调 ceiling 重渲，≤3 次）→ out/<id>/{clean.m4a,edit.json,report.json}
```

关键实现要点（都有实测依据）：

1. **真峰值限幅（不是采样峰）**：4× `resample_poly` 测峰 → 逐样本 `g_req = ceiling/tp` →
   前瞻 `minimum_filter1d`（5 ms）+ O(n) 滑动平均释放（150 ms）→ 乘法增益；内部再回读 4× TP，
   过冲 >0.1 dB 就下调 ceiling 重做（≤3 次）。分块 120 s + 1 s context（f04 clean 358M 样本，
   整段 4× float64 要 11 GB）。实测 wav 4× TP 与 ebur128 `peak=true` 一致（差 ≤0.05 dB）。
2. **m4a 真峰值闭环是必须的**：AAC 编码在硬限幅瞬态上会产生 **+0.2 ~ +5.8 dB** 的码流过冲
   （见下表 `wav TP→m4a TP`），只看 wav 限幅结果会漏掉。闭环实测：f05 wav TP −2.74 → m4a **+3.10**
   （过冲 5.8 dB）→ ceiling 下调到 −7.35 后 m4a −5.10；f20 wav −2.60 → m4a **+0.50**（过冲 3.1 dB）
   → ceiling −4.75 → m4a −1.90；f00 −2.65 → −1.30（过冲 1.35）；f24 −2.74 → −2.50（0.24）。
3. **ASL 口径与 P2 完全一致**：复用 `analyze.frame_power`（25 ms 窗/10 ms 跳）+ `p56_level(rel_db=15)`
   + 帧中心落在「连续语音段（≥3 s）映射到 clean 轴」的掩码内；先降采样到 16k 再测（与 P2/PoC 同轴）。
4. **V2 写成相对式** `g = clip(base + (ref − level), base ± clamp)`（ref = clean16 全段 P56 = asl_in）：
   首次渲染与锁定式严格等价，但 ASL 校正迭代时 base 平移能带动 V2 包络（否则 f00/f05 这种
   限幅掉 0.7–1.5 dB 的文件会卡在偏差上）。跨轮（ceiling 变化）把上一轮收敛的 base 作为
   `gain_offset` 传给下一次 render，少爬 1–2 遍（f05 从 4 遍降到 3 遍）。
5. **降噪**：`highpass=f=80,afftdn=nr=12:nf=-30:tn=1` @44.1k；f00(SNR 10.8)/f06(7.8) 按配置
   自动升 `nr=16`；arnndn 走 `cd` 模型目录 + 相对 `m=sh.rnnn` + 48k `aresample` 进出（已冒烟验证）。
6. **中间文件清理**：只删本阶段产生的 wav（denoised/clean/normalized + 44.1k 解码缓存），
   **保留 16k 与 `*.analyze.json`**（初版误用 `decode.cleanup_cache` 会把 analyze 缓存一起删掉，
   已修：`render_job` 只按显式路径删）。

### 决定（先定后写码）

1. **export 阶段语义（P6 自己合并，不读旧 metrics 判完成）**：`export` = 最终全部产物落盘
   （audio + transcript + corrections + md/srt/txt）。render_job 的 `export` 回调只缓存在
   `audio_export_metrics`，**不单独落库**；全部阶段结束后统一 `start_stage(export, reset=True)`
   + `finish_stage(export, done, merged)`，merged = audio（tp_dbtp/asl_out_dbfs/size_bytes）
   + text（md/srt/txt + n_written）+ transcript（n_segments/chars）+ corrections
   （total/rejected）+ speakers（n/method）。`finish_job(done, stage="export")` 只由编排器调一次。
2. **resume 判定以产物为准**：8 件文件齐全 + `report.asr` / `report.correct` / `report.speakers`
   都是对象 → `skipped`（不重跑 render/ASR）；缺哪段补哪段（缺 `diarize` stage 只补该行，
   不整条重跑）。`batch --resume` 对 done 任务全 skip，`--force` 才重跑。
3. **清理策略**：编排器成功后只删 `<id>.clean16k.wav`；`<id>.16k.wav` / `<id>.analyze.json` /
   `<id>.decode.json` **必须保留**（删 16k 会让 analyze 缓存失效，resume 变慢）；render 的
   `.denoised44k/.clean44k/.normalized44k` 与 44.1k 解码缓存由 render_job 自己清。
   `--keep-intermediates` 透传 render_job 并跳过 clean16k 清理。**不调用** `decode.cleanup_cache`。
4. **锁**：`work/locks/<job_id>.lock`，`O_CREAT|O_EXCL` 写入 `pid\tts`；持锁进程已死
   （Windows 用 ctypes `OpenProcess` 探测，POSIX 用 `os.kill(pid,0)`）→ stale 锁清掉重抢。
   `run_job` 自己抢锁，抢不到返回 `{ok:false, locked:true, stage:"lock"}` 且**不写 DB**；
   Web 的 run 端点另用进程内 running 集合先判 409。
5. **事件与落库**：`on_event(stage, status, metrics)` 与 render_job 同签名；非 export 阶段

8. **attempts 上限**：`batch.max_attempts`（默认 2）；batch 中 `attempts >= max_attempts` 且

9. **新依赖：不新增**。上传走 `application/octet-stream` 裸流 + `?filename=`；API 验收用标准库

### 偏差 / 遗留

1. **ASR 期间 `jobs.stage` 显示滞后**：P4/P5 模块只在阶段完成时回调，编排器在调用 `transcribe_job` 前没有
   `start_stage(asr)`，所以 ASR 跑动中 `jobs.stage` 仍是上一个已完成阶段（`loudness`）；Web 显示
   `status=running + stage=loudness`，阶段 chip 仍能看出进度（render 段已 done）。P7 不阻塞，后续可在
   `_invoke` 前补 `start_stage` 让 stage 实时。
2. **改字会把 transcript.json 换行风格从 CRLF 规范为 LF**（服务端原子写用 `\n`）：JSON 内容不变，
   md/srt/txt 逐字节不变；验收里改回后已用备份恢复 P4 原始字节。若要求严格保留换行风格，可在
   `_atomic_write_json` 用 `newline=""` + CRLF。
3. **batch resume 会补记 stage 行**（6 个历史 job 补 `diarize`）：只改 DB 状态（`metrics.backfilled=true`），
   `out/` 产物 0 改动；这是「缺哪段补哪行」的实现方式。
4. **`--json` 语义收紧**：`main()` 在 `--json` 时把 console 日志关掉（只进 `out/logs/run.log`），
   stdout 为纯 JSON；非 JSON 模式日志照旧在 stdout。
5. **接口附加键**（不破坏契约）：`batch_run` 返回 `skipped_reasons`；`run_job` 返回 `stages` map；
   `artifacts.mtime` 是 Unix 秒浮点；server 的 run 在编排器模块缺失时返回 503（并行期兜底，正常不触发）。
6. **上传/改字阈值**：单上传 2 GB（超限 413）、单段 text ≤5000 字、扫描路径不存在 404；如需调整改常量。
7. **kill/resume 证据口径**：强杀点落在 ASR 写出 transcript.json 之后（DB 里 asr 行尚未落），resume 时
   render 与 ASR 都按产物跳过、stale 锁被清理、最终产物齐全；这与「已完成阶段不重跑」一致。
