## 1. 方法

### 1.1 流程

```
data/*.m4a ──ffmpeg──> 16k 单声道 wav
   │（若 work/audio-edit/<短名>/clean.wav 存在，则改用 clean 音轨 + mapping.json）
   ├─[1] Silero VAD（32ms 原生窗流式概率，LSTM 状态顺序推进）
   │      └─ 硬回差判决 → 语音段 [0.5s, 30s] → 段后处理 → 边界 10ms 能量谷精修
   ├─[2] 逐段 SenseVoiceSmall(int8, sherpa-onnx) 解码 → 每段文本
   ├─[3]（可选）sherpa-onnx 离线 diarization（pyannote-seg + cam++ + FastClustering th=0.7）
   │      └─ 段级 embedding 质心 + 平均链接层次聚类归并（10 分钟抽样验证用）
   └─[4] 拼装：VAD 段 × ASR 文本 × 说话人 × clean/orig 时间映射
          → transcript.json / transcript.md / transcript.srt
```

### 1.2 为什么不用"30s 分块 + 字符比例估时间"

前期 78 分钟整片转写用的是"30s 硬切块 → 整块 ASR → 按字符数把块内时间平摊给每句"。块内语速并不均匀（讲课有停顿、重复、笑声），这种线性假设的句级误差可达**数十秒**，且块边界会把词切半。本 PoC 的时间直接来自 VAD 判决出的语音段边界，ASR 只在段内解码，段的 start/end 就是句级时间戳——不存在"估"的环节。

### 1.3 VAD：Silero 的真实分辨率与 10ms 边界

- 模型：`faster_whisper/assets/silero_vad_v6.onnx`（faster-whisper 自带，1.2MB），16k 下单窗 512 样本 = **32ms**，LSTM 状态 (h,c) 顺序推进。**v5/v6 模型本身没有 10ms 窗**。
- 实测过"把窗按 160 样本（10ms）滑动、状态顺序携带"的写法：LSTM 状态演化速度变成 3.2 倍，概率崩塌（60s 样本 `p≥0.5` 占比从 55% 掉到 2%），**不可用**。因此采用官方 32ms 流式概率。
- 判决：`threshold=0.5`，回差 `neg_threshold=0.35`；候选静音连续 ≥ **0.45s** 才断句；语音段 < **0.6s** 并入邻近段；段 > **30s** 时在 `[30s-8s, 30s]` 内找概率最低点强制切开（避免切字）。
- **边界 10ms 精修**：对每段起止在 ±180ms 内用 10ms hop 短时 RMS 找局部能量谷并吸附。最终边界落在 10ms 网格上，抵消 VAD 32ms 窗带来的滞后/提前。
- 段后处理：相隔 <0.20s 的段合并；<0.6s 碎段并回邻近；两端各补 0.12s 作为 ASR 解码窗（解码窗不参与上报时间；上报用精修边界）。

### 1.4 ASR：逐段 SenseVoice，不跨段拼接

- `sherpa-onnx.OfflineRecognizer.from_sense_voice(model.int8.onnx, tokens.txt, num_threads=8, use_itn=1, language="zh")`。
- 每段独立建 stream 解码，**不把多段拼起来再切**，保证时间戳与文本一一对应。
- 文本清洗：去掉 `<|zh|><|NEUTRAL|>` 类标签与 emoji；去掉所有空白。
- 统计口径：`asr.json` 里 `n_empty` 指"文本为空串"的段（本文件 0）；但存在"只有标点、没有汉字/字母/数字"的段（如 `。`），这类在 md/srt 中不输出，计为 **`n_no_content`（本文件 3 段）**——报告正文一律用"有内容段/无内容段"两个口径，不再说"0 空段"。

### 1.5 说话人：默认单标签 + 抽样 diar 验证

本批 6 个文件都是**单人讲课**（前期 `docs/research/diarization-poc.md` 已证明 24_形而上学：「主讲人语音 3284.4s = 全片 70.3%，占真人语音 97.6%，实质只有 1 个主讲人」）。因此生产默认：

1. 逐段 `speaker="主讲"`，不做全片 diarization（78 分钟全片 diar 在本机 CPU 上要 6–12 分钟，收益极低）；
2. 需要验证/遇到多人录音时，才在 **10 分钟片段**上跑 `threshold=0.7` 的 sherpa diarization + 二阶段归并（§4）；命中"其他"标签的段才改标签；
3. **保守策略**：重叠不足（<30% 段长）或簇总时长 <3s 的段一律标「主讲」——宁可漏标"其他"，不臆造发言人。

### 2.1 耗时与资源（clean 音轨，8 线程 CPU）

| 环节 | 墙钟 | RTF | 说明 |
|---|---|---|---|
| 解码到 16k 单声道 | 0.4s | 0.0001 | clean.wav 本身即 16k，转成 PCM16 缓存 |

| SenseVoice 785 段逐段解码 | **100.5s** | **0.0259** | 纯解码 94.2s；模型加载 2.0s |

| **端到端** | **≈115s（1.9 min）** | **0.0297** | 64.6 min → 1.9 min |

> 原始音轨上的同链路（928 段，含片头/片尾非讲课内容）：VAD 25.6s、ASR 204.4s（RTF 0.0437）、端到端 ≈234s（3.9 min）。clean 版更快，一是非讲课段被裁掉（少 763s 待解码音频），二是段数从 928 降到 785（短段固定开销占比下降）。
> 对比前期"30s 分块"整片 RTF 0.0301（140.5s / 77.9min）：分段 ASR 在原始音轨慢 45%，在 clean 音轨上反而更快——因为 VAD 不把长段音乐/掌声送进 ASR。

## 3. 时间戳精度验证（10 分钟样本）

方法：在**原始 16k 音轨**的 600–1200s（讲课正文）上，用 **faster-whisper base（CPU int8, beam5, `word_timestamps=True`）** 解出词级时间戳作参照（1758 词）。对窗口内每个 VAD 段，取"词中点落在该段内"的首词 start / 末词 end 作参照边界，统计 `我们 − 参照` 的有符号误差与绝对误差。本文件共匹配 133 段。

| 口径 | 样本数 | 误差中位 | 平均 | 标准差 | **P90 绝对误差** |
|---|---|---|---|---|---|
| 段起点 | 133 | **+0.22s** | +0.23s | 0.58s | **1.07s** |
| 段终点 | 133 | **−0.47s** | −0.23s | 0.61s | **0.95s** |

> 复核脚本：`work/cost/ts_eval.py`（团队统一口径，参照 transcript.json 的 928 段原始音轨版本）。本报告另有一次独立复跑（同窗口、base 1694 词、130 段）给出同量级的**绝对误差**：起点中位 0.21s / P90 0.65s，终点中位 0.36s / P90 0.93s。

**读法**：

1. **起点 +0.22s（偏晚）**：Silero 需要"连续几帧超过阈值"才起段，天然晚于真实音头；0.2s 量级符合 VAD 回差设计。
2. **终点 −0.47s（偏早）**：VAD 在候选静音开始时结束段，而参照（whisper 末词的 end）通常包含尾音/拖长；加上"VAD 在停顿处切句、词边界在词内/词间"的口径差，终点系统偏早约 0.5s。这是**口径差 + VAD 回差**，不是时间轴漂移。
3. **参照本身也有误差**：用 whisper base 与 whisper small 对同一窗口的词级时间戳做序列对齐（1038 个匹配词）——两模型边界差中位仅 **0.02s**、P90 绝对差 **0.28s（起点）/0.08s（终点）**，说明"参照抖动"在 0.1–0.3s 量级；本次 0.2–0.5s 的边界差中约一半可归因于参照/口径，剩余是 VAD 回差。
4. **量级对比**：前期"30s 分块 + 字符比例估时间"的句级误差可达数十秒；本方案中位 0.2–0.5s、P90 <1.1s，**误差小 1–2 个数量级**，已满足人工校对/SRT 起步要求（专业字幕对齐目标通常是 ±0.2s，还需词级 forced alignment 才能达到）。
5. **P90 尾部（~1s）**主要来自"VAD 段与参照词不完全对齐"的段（VAD 把一句切成两段、或把两句并成一段）——属于**分段口径差异**，可通过把 `min_silence` 调到 0.3–0.35s 或做词级再对齐进一步压。

## 4. 发言人标注：策略与稳定性

### 4.1 默认单标签（生产口径）

本批录音均为单人讲课（前期 diarization PoC：24_形而上学主讲人占真人语音 97.6%）。最终转写全部 785 段默认 `speaker="主讲"`。全片 diarization 在 CPU 上要 6–12 分钟，对"单人课"收益为零，因此**不进默认链路**；`transcript.json` 的 `spk_cluster`/`spk_conf` 字段已为接 diar 预留。

### 4.2 抽样验证：原始音轨 600–1200s 片段跑 sherpa diarization（threshold=0.7）

| 项 | 值 |
|---|---|
| 输入 | 原始音轨 600–1200s（10 min），82 个 diar 段 |
| 处理耗时 | 166s（与另一路 ASR 并发，CPU 争用下；独占约 45–60s，RTF≈0.08–0.10） |
| 原始说话人数（th=0.7 直跑） | **8 簇** |
| 主簇时长 / 占语音 | **506s / 92.6%** |
| 二阶段归并（cam++ 质心，cos 0.7） | **8 → 6 簇** |
| 归并后主簇 | **539s / 98.5%** |
| 归并扫描 | th 0.5→5 簇、0.6→5、0.7→6、0.8→7、0.9→7；主簇 543→534s 基本不随阈值变 |

对照前期 `docs/research/diarization-poc.md`（同文件 600–1200s）：th=0.5 时 15 簇/主讲 87.4%、th=0.6 时 11 簇/91.4%。本次 th=0.7 直跑 8 簇、92.6%，归并后 98.5%，与"1 主讲 + 少量插话/碎片"的结论一致。

### 4.3 标签稳定性与"不臆造"策略

- **同一人被拆多 id 确实存在**：th=0.7 直跑 8 簇里，**4 簇总时长 <3s（合计 4s）**，且 **3 簇与主簇质心 cos≥0.6（合计 37s）**——即主讲的短句/远场片段被单独聚成新 id；归并后这部分并回主簇，主簇从 92.6% 升到 98.5%。
- **归并前后差异**：说话人数 8→6；对最终转写的影响是"其他1/其他2"两三个短标签消失，正文段落不再被无意义地切成多人对话。
- **保守规则（已实现于 `step_build.py`）**：
  1. 段与 diar 结果的最大重叠 <30% 段长 → 标「主讲」；
  2. 簇总时长 <3s → 不单独造身份，标「主讲」；
  3. 只有总时长 ≥3s 的非主簇才编号「其他1/其他2…」。
- **结论**：本批文件可安全用单标签；若将来接入多人录音，th=0.7 + 二阶段归并 + 上述保守规则即可，宁可少标不可臆造。

## 5. 局限与坑

1. **参照自身的误差**（见 §3 末）：faster-whisper 的中文词级时间戳来自 cross-attention，本身有 0.1–0.3s 抖动；VAD/ASR 段边界与词边界不是同一概念（VAD 在停顿处切句，可能落在词组中间），所以误差里混有"分段口径差异"。
2. **音乐/掌声会被 VAD 当语音**：原始音轨片头 0–8min 与片尾的 BGM/环境声被判为语音，SenseVoice 产出「我去做饭」「我在。关。」这类幻觉短句（存档在 `orig_axis/transcript.md`）。本次最终产物改用 audio-edit 的 clean 音轨，问题已基本消除；若没有 clean 音轨，生产上应先按前期结论做头尾裁剪（0–480s、4520s 之后）或对无汉字/极短低置信段做丢弃。
3. **clean 映射跨删除段时 orig 时间是近似的**：VAD 段若跨在 clean 拼接缝上（极少，本文件 785 段中个别段），其 orig_start/orig_end 会跨越被删区间、orig 跨度远大于 clean 时长（属"双时间"的天然限制，json 里两套时间都在，SRT 用 clean）。
4. **SenseVoice 同音错字**：形而上→"学而上/形儿上学"、原著选读→"原助选读"、刘晨光→"刘春光"等，属模型能力问题；上热词/后校对可解，不影响时间轴。
5. **ASR RTF 受段数影响**：928 段短段解码比 30s 分块慢 45%（原始音轨对照）。若要提速，可考虑 sherpa-onnx 的批量/多流解码，或把段合并到 15–25s（牺牲段内时间分辨率）。clean 音轨上段数降到 785 后 RTF 0.0259，已优于 30s 分块。
6. **全片 diarization 在本机 CPU 太贵**：并发下 78 分钟全片 diar 超过 12 分钟仍未完成（与前期 8 线程独占 352.8s 差距大，主要是多任务争用），故按任务要求只做 10 分钟抽样；生产若真要多发言人整片标注，建议 GPU 或分段并行。
7. **只完整跑了 1 个文件**：本轮时间盒内只对 24_形而上学 做了全量端到端（任务要求 ≥1）；其余 5 个文件未跑，脚本对任意文件通用（`--short/--src` 换掉即可，预计每 78 分钟 2–4 分钟）。

## 6. 生产建议

1. **默认链路**：audio-edit clean 音轨（或原始音频）→ VAD 分段（th=0.5/回差 0.35/最短静音 0.45s/最长 30s/10ms 精修）→ 逐段 SenseVoice → 单标签「主讲」→ md/srt/json（clean+orig 双时间）。本机 64.6→1.9 分钟，纯 CPU 可接受。
2. **先裁头尾再转写**：clean 音轨已裁掉 17.1% 非讲课内容，转写质量与速度双收；没有 audio-edit 时按前期结论裁 0–480s、4520s 之后。
3. **SRT 后处理**：按字幕规范把 <0.8s 的 cue 合并到相邻 cue、单条 >42 字符时按标点拆分；演讲类内容建议按自然段（本 PoC 的 md 段落）生成软字幕。
4. **时间轴与音频编辑对齐**：走 clean 音轨时用 mapping 输出双时间；SRT 默认用 clean 时间（所见即所得），校对稿用原始时间（对得上原始录音）。
5. **多人场景**：10 分钟分段 diar（th=0.7 + 二阶段归并）先试点，只有"其他"总占比 >5% 的文件才需要全片 diar；标签只给"主讲/其他N"，不给真实姓名。
6. **提升对齐精度**：若要 ±0.2s 级字幕，可在本方案后加一步 **whisper 词级 forced alignment**（给每段文本与音频做词级对齐），把句边界重算到词边界。
7. **可复现**：`python -X utf8 work/timeline/scripts/run_file.py --short <短名> --src <m4a> --outdir work/timeline/<短名> --threads 8`；10 分钟抽检用 `step_eval.py`。
