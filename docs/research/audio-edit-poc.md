# 音频编辑管线 PoC：降噪 + VAD 裁剪 + 语音电平归一化（V1/V2/V3 对比）

> 任务：需求 1（降噪）、需求 2（裁剪）、需求 3（音量稳定化/跨文件一致）、需求 4（保守去无关人声）
> 数据：`data/` 下 6 个 m4a，共 **576.0 min**（34563 s），全部为本机实测，无估算。
> 产物：`work/audio-edit/<短名>/{clean.wav, mapping.json, stats.json}`、`work/audio-edit/report.json`、
> `work/audio-edit/ab/`（3 组 20 s A/B）、`work/audio-edit/scripts/`（可复跑管线）。
> 环境：Windows 10 / i5-12400F（12 线程）/ 32 GB / `work/venv`（sherpa-onnx 1.13.8、onnxruntime 1.23.2、numpy/scipy/matplotlib）；ffmpeg 7.1。

## 0. 一句话结论

**推荐 V2（静态增益 + 慢变自适应）**，目标 `speech_asl = -20 dBFS`：

- 6 个文件处理后 `speech_asl` 极差 **0.08 dB**（σ=0.028，最大偏差 0.08 dB），远优于 ±0.5 dB 目标；
- 同一文件 5 min 窗口 p5–p95 半展宽 **0.26–1.44 dB**（V1 为 1.50–4.12 dB），满足 ±1.5 dB；
- 限幅后真峰值除极安静源 xfzx 的 V2（-0.90 dBTP，残余超 0.1 dB）外全部 ≤ -1 dBTP，无削波；
- V2 增益变化率 0.61–0.99 dB/s、限幅触发 0–2.64%，未见泵动/削波；LRA 由 V1 的 9.5–14.1 LU 降到 7.8–9.3 LU。

**V3（按说话人静态增益）默认关闭**：6 个文件都是单人讲课（非主讲语音占比 ~2%），V3 退化为 V1；且在 xes 上用官方 diarization 验证时，非主讲小簇增益仍偏差 +1.8~+4.1 dB，属负结果。
**降噪**默认 `highpass=f=80,afftdn=nr=12:nf=-30:tn=1`（RTF 0.002–0.003）；`arnndn` 噪声抑制更强（-12.35 dB）但语音也 -2.24 dB 且需 48 kHz，只建议作为噪声更差源的可选档。
**裁剪本身很有效，但头边界精度不够**：6 文件内部长静音切除共 1954 s（xes 一家 763 s，主体就是片头 8 min 音乐/长停顿被当"内部长静音"切掉，整体裁剪率 6.9%，xes 达 17.1%）；但 VAD 把 xes 片头 7–48 s 的部分音乐误判成"连续语音"，clean 开头仍残留约 **31 s** 音乐（kept `[7.28,37.63]`+`[47.01,48.06]`）。生产上用 **120 s 窗口 ASR 字符率**判 head（f24= xes：0–480 s 均值 0.24–0.47 字/s，480 s 后跳到 2.26 字/s），把残留的 ~31 s 也切掉（见 §7.2）。

## 2. 方法

### 2.1 VAD 与语音段（需求 1 的基础）

- 模型：**Silero VAD**（本机 `faster_whisper` 内置的 `silero_vad_v6.onnx`，经 onnxruntime；属于 Silero 系而非 sherpa 自带模型，因 sherpa 需要单独下载的 `silero_vad.onnx` 而本机网络到 GitHub 超时）。Silero 原生按 **512 样本（32 ms）** 窗输出语音概率；本实现把判决投影到 **10 ms 帧网格**（帧中心落在语音段内 = 语音帧），与任务要求的 10 ms 帧分析口径衔接。
- 参数：`threshold=0.5`、`min_speech_duration_ms=250`、`min_silence_duration_ms=300`（=合并 <0.3 s 空隙）、`speech_pad_ms=0`。这两项正好等价于任务要求的"合并 <0.3 s 空隙、最短段 0.25 s"。
- 段分类：`dur ≥ 3 s` 为**连续说话段落**（cont），`dur < 3 s` 为**碎片**（frag）。后续需求 3 的电平测量、需求 4 的排除逻辑都只认 cont；碎片只保留不参与电平统计。
- 语音占比（VAD 段总长/总时长）：61.8%–81.6%；连续段合计 1097–4164 s，碎片合计 995–2215 s（碎片占比确实高：本数据是讲课，句间停顿 >0.3 s 就会断开，因此"连续段"只覆盖约一半语音；这是任务书给定口径，已在 §8 局限中注明）。

### 2.2 降噪

- 默认链：`highpass=f=80,afftdn=nr=12:nf=-30:tn=1`（需求给定），整片一次性过滤，输出 f32。
- 对照：`arnndn`（rnnoise 模型 `work/bench/models/rnnoise/sh.rnnn`）+ 仅 `highpass`。
- **arnndn 的采样率坑**：rnnoise 只支持 48 kHz，直接把 16 k 送进 `arnndn` 时 ffmpeg 会把输出变成 48 k（长度×3），后续按 16 k 读会全错。正确链：`aresample=48000,highpass=f=80,arnndn=m=sh.rnnn,aresample=16000`。另注意 filter 参数里不能出现 Windows 路径冒号，需 `cd` 到模型目录用相对文件名。
- 评估只在**语音段内/长停顿空隙内**统计（不用整段指标，避免片头音乐污染），3 个文件各取 5 min 正文（xes 600–900 s、wlx 1200–1500 s、ly 2400–2700 s）。

### 2.3 裁剪（需求 2）

- 片头/片尾：以**首个/末个 ≥3 s 连续语音段**为界，各留 0.3 s，其余整段删除。
- 内部长非语音：VAD 段之间的空隙若 **≥3 s**，从输出中切除，但两侧各留 **0.25 s 保护带**（切 `[gap_start+0.25, gap_end-0.25]`）。
- 输出紧凑时间轴 `clean.wav`（16 k mono），并输出 `mapping.json`：
  - `kept`: `[[orig_start, orig_end, clean_start, clean_end], …]`（秒，多段按顺序拼接）；
  - `removed`: `[{start,end,reason}]`，`reason ∈ {head_trim, tail_trim, internal_pause}`；
  - `crop`: 头/尾/内部切除秒数、裁剪比例、语音保留率等。
- 语音保留率用"VAD 段 ∩ kept 区间"验证：连续段 **100%**，全部语音段 **99.4%–99.9%**（差额来自头尾 trim 会切掉边界外的短碎片）。

### 2.4 语音电平测量（P.56 思路，只算连续段语音帧）

对每个 10 ms 帧（20 ms 窗）算均方功率 `p_k`，只保留帧中心落在 cont 段内的帧，然后：

```
L0 = 10·log10(mean(p_k))                  # 初始电平
T  = L0 - 15 dB                            # 活跃门限（相对本窗口/整段）
active = {k : 10·log10(p_k) > T}
L1 = 10·log10(mean(p_k | k∈active))       # 重算电平，迭代至 |ΔL|<0.01 dB（≤20 次）
speech_asl_dbfs = L_final
```

- 这是 P.56 "active speech level" 的简化实现（迭代门限法），不是标准 P.56 的 15.9 dB/h 活动因子流程；对本项目只需**同一口径可复现**，跨文件相对值有效。
- 同时给 p10/p25/p50/p75/p90（连续段语音帧 dB 分布）。
- 5 min 窗口波动：按 300 s 无重叠窗口分别算 ASL（窗口内语音不足时跳过），报 p5/p95 及其差值（spread）与半展宽（half = spread/2，对应"±dB"）。6 文件窗口数 10–28 个。
- EBU R128 对照：ffmpeg `ebur128=peak=true` 测 integrated LUFS / LRA / true peak(dBTP)。**LUFS − ASL = -0.2 ~ -3.3 dB**（xfzx 差 -3.3），且跨文件 LUFS 极差 32.7 dB 与 ASL 极差 31.4 dB 不同源，证明"整段 LUFS"不适合做语音统一（片头音乐/长静音会拉偏）。

### 2.5 三变体

- **V1 静态增益**：`g = T − speech_asl`，整文件一个增益（保真最好，不解决文件内波动）。
- **V2 静态 + 慢变自适应**：
  - 20 s 窗 / 5 s 跳步，在窗内用同一 ASL 口径求 `g_w = T − asl_w`，限制 `g_w ∈ [g−C, g+C]`（默认 C=3 dB）；
  - 对窗增益做 3 点滑动平均 → 控制点级变化率上限 1.5 dB/s → 插值到 20 ms 块 → 1 s 平滑 → 再次夹到 ±C；
  - 应用时按 **20 ms 块余弦交叉淡化**（块内从前一块增益升余弦过渡到本块增益），避免台阶声；
  - 施加后用同一 ASL 口径回测，超 ±0.03 dB 时整体再校正（最多 3 轮）。
  - 自适应档位：默认 C=3 dB；**wlx 因片内 5 min 波动达 ±4.1 dB、±3 dB 压不进 ±1.5，单独放宽到 C=6 dB**（仍满足 20 s 窗/1 s 平滑/≤1.5 dB/s），并在报告里标出（`v2_clamp_db`）。
- **V3 按说话人静态增益**：用 sherpa-onnx diarization 给每段打 spk（官方 OfflineSpeakerDiarization 结果或 cam++ embedding 聚类），主讲人（时长最大簇）及其余说话人分别归一到 T，边界 20 ms 交叉淡化，每组语音不足 5 s 时退回主讲增益。
- **限幅**：全部变体统一 `alimiter`（attack 5 ms / release 50 ms / `level=0` 关闭自动补偿），采样峰 ceiling 初值 **-2 dBFS**；渲染后回读真峰值，若 > -1 dBTP 则按"真峰值相对取样限幅点的过冲"精确下调 ceiling 并重做（最多 2 次）。当前实现见 `scripts/run_one.py::render_variant`。

### 2.6 模拟"不同来源"试验

取 3 个文件（xes/wlx/ly）各 5 个语音段（约 7–18 s，取自不同时间点），人工加 **-12/-8/-4/+3/+6 dB** 偏移（覆盖安静到过载），再走同一 V1 归一化+限幅，验证输出是否回到 T±0.5。

## 4. 模拟"不同来源"试验

3 文件 × 5 段，人工加 -12/-8/-4/+3/+6 dB 后走同一 V1 归一化+限幅：

- 15/15 段输出回到 -20 ± 0.5 dB；
- **max |dev| = 0.041 dB，mean |dev| = 0.015 dB**；
- 输入 ASL 覆盖 -33.5 ~ -3.6 dBFS（跨 30 dB），含 +21.5 dB 的系统性电平差修正能力验证。
- 明细：`work/audio-edit/sim_offsets.json`。

结论：**只要测量口径固定（连续段语音帧 + P.56 式 ASL），静态归一化对来源差异的鲁棒性足够**；难点不在电平估计，而在①真峰值/削顶保护、②片头音乐误判、③文件内慢变。

## 5. V1 / V2 / V3 对比与推荐

| 维度 | V1 静态 | V2 静态+慢变 | V3 按说话人 |
|---|---|---|---|
| 跨文件 ASL 统一 | ✅ 极差 0.12 dB | ✅ 极差 0.08 dB | ≈V1（退化为常数增益） |
| 同文件 5min 波动 | ❌ 5/6 文件超 ±1.5 dB | ✅ 6/6 ≤1.44 dB | ❌ 同 V1（2.21 dB） |
| 保真/伪影 | 最好（一个常数增益） | 好（0.6–1.0 dB/s，无削波） | 差（小簇增益映射不稳） |
| 计算/复杂度 | 极低 | 低（多 1 次渲染） | 高（diarization 或 embedding） |
| 适用 | 保真优先、后续还要拼接/变速 | **默认** | 真正的多人课堂（需更稳 diar 标签） |

**V3 为什么不推荐（负结果）**：

1. 6 个文件均为单人讲课（xes 官方 diarization：主讲人 97.6% 语音，非主讲仅 ~152 s/4673 s ≈3.3%，其中大量是 <1 s 碎片）。V3 在这些文件上退化为 V1。
2. 在 xes 上用官方 diarization（72 簇）做 V3 实测：渲染后整段增益仍为常数（gain -7.39~-7.39 dB，V3 out = V1 out），**非主讲组残余 +4.09 dB（S5，11.7 s）/ +1.84 dB（S9，6.6 s）**——因为 VAD 段到 diar 簇的"中点投票"映射把短簇吞并进主讲；把 diar 标签映射成帧级增益时，20 ms 交叉淡化也救不了"整段没有该簇帧"的问题。
3. 10 min 试跑里用固定余弦阈值 0.75 的 embedding 聚类：cam++ 在 3 s 短窗上的同人余弦只有 ~0.5–0.65，**直接裂成 27 簇**，V3 增益在簇边界出现 ±5 dB 级跳变、最大变化率 8.56 dB/s（不可接受）。改用"主讲人占比 ≥98% 先验 + 平均链接"后虽然退化为 V1，但也说明**当前数据上 V3 没有收益**。
4. 结论：V3 保留实现（`scripts/speakers.py` + `run_one.py --variants v3`），**默认关闭**；只有出现真正多人讨论、且 diarization 能给出 ≥5 s 稳定非主讲簇时才启用。

## 6. 降噪对照（5 min 正文 × 3 文件，`denoise_compare.json`）

| 处理 | 语音段 RMS 变化 | 长停顿噪声 RMS 变化 | SNR 代理变化 | RTF（16 k） | 结论 |
|---|---|---|---|---|---|
| 仅 `highpass=f=80` | -0.66 dB | -1.90 dB | +1.24 dB | 0.0003 | 低成本，主要去低频隆隆声 |
| `highpass + afftdn(nr=12,nf=-30,tn=1)`（默认） | **-0.23 dB** | -1.26 dB | +1.03 dB | 0.0024 | 语音几乎不动，稳态噪声小幅下降，**安全默认** |
| `highpass + arnndn`（48 k 进出） | -2.24 dB | **-12.35 dB** | **+10.11 dB** | 0.0085 | 噪声抑制最强，但语音也被压缩 2.2 dB，低码率源上有"水下感"风险；需 A/B 后再用 |

- 逐文件差异大：ly 的低频噪声严重，仅 highpass 就把噪声 -5.5 dB、SNR +3.7 dB；wlx 某 5 min 段 afftdn 反而让噪声 +2.6 dB（afftdn 噪声学习被音乐/混响干扰）。
- 推荐：**默认 afftdn 链**；若某文件实测底噪明显（可先用本脚本 5 min 抽样判断），再上 arnndn，并对该文件单独做 A/B 试听。

## 7. 两个必须写清的坑

### 7.1 真峰值：样本峰限幅 ≠ -1 dBTP（实测最高 +0.80 dBTP）

- 首轮 6 文件用 `alimiter limit=-2 dBFS`（采样峰 ceiling）：lxg1 V2 实测 **+0.80 dBTP**、xfzx V2 +0.80 dBTP、xfzx V1 +0.80 dBTP——**不达标**。
- 原因：`alimiter` 限的是**采样峰值**；本批源大多带削顶/超采样过冲（源 true peak 最高 +5.7 dBTP），16 k 重采样后高频/瞬态重建会让 4× 过采样真峰值比采样峰值高出 **2.6–2.8 dB**（xfzx 实测 2.8 dB）。原始设定 -2 dBFS 采样峰对应真峰值可达 +0.8 dBTP。
- 修复（已实现）：渲染后回读 `ebur128(peak=true)`，若 > -1 dBTP，则 `new_ceiling = -1 - (tp - ceiling) - 0.3` 精确补偿并重做（最多 2 次）。修复后：lxg1 -1.1/-1.3、xfzx V1 -1.3，**仅 xfzx V2 残余 -0.90 dBTP**（超 0.1 dB）。
- **生产建议**：① 直接用真峰值限幅器（如 `alimiter` 之外的真峰值/4× 过采样限幅，或 `loudnorm` 的 `TP=-1.5` 门控），ceiling 设 **-2.5 ~ -3.0 dBFS**，不要用 -2.0；② 对源 true peak > 0 dBTP 的文件（xfzx/xes/lxg4）在归一化前先做一次 declip/限峰，别把削顶瞬态放大 +20 dB 后再压（xfzx 需把满刻度瞬态压掉 24.7 dB，会带来瞬态软化/失真风险）。

### 7.2 头边界不能只用 VAD：内部静音切除拿走了 80–90% 收益，但 xes 开头仍残留 ~31 s 音乐

- **正确表述**：xes 的 `head_trim` 只有 7.3 s，但片头音乐并没有"没切"——7–480 s 的音乐绝大部分被当作**内部长静音**切掉了（xes 内部切除 763.2 s 的主体；`mapping.json` 里 kept 从 7.28 s 开始，`[7.28,37.63]`、`[47.01,48.06]` 之后直接跳到 `[514.47,…]`）。VAD-only 的裁剪已经能拿到 **80–90% 的收益**。
- **残留问题**：VAD 把 7–48 s 的部分音乐误判成"连续语音"，因此 clean 开头仍保留 **~31 s** 音乐（30.35 s + 1.05 s 两个 kept 区间），重转写时开头会出现"我去做饭"这类幻觉段。
- **修复（生产必须加）**：用 **120 s 窗口 SenseVoice 字符率**判 head——从文件开头每 120 s 转写一次，找第一个 `字符率 ≥ 1.5 字/s 且其后连续 2 个窗口仍 ≥1.5` 的位置作为讲课起点，再回退到该窗口内首个 ≥3 s 连续语音段；片尾反向同理。scan 组实测 f24(=xes) **0–480 s 均值仅 0.24–0.47 字/s，480 s 后跳到 2.26 字/s**（`work/scan/head_scan.json`），正好把残留的 ~31 s 圈在阈值以下。
- 按此规则 xes 还会再剪掉约 31 s；其余文件（lxg1/ly 头剪 142/146 s）恰好落在音乐结束处，属"运气好"，不能依赖。
- VAD 只负责段内边界（切长静音），"这一段是不是讲课"必须用 ASR 字符率/文本语义判定。

## 8. 需求 4：保守去无关人声（xes 实测，`req4_candidates.json`）

- 官方 diarization（`work/diar/final_diar.json`，72 簇）：主讲人 0（3340 s），非主讲语音合计 152.2 s（≈3.3%，多数 <1 s 碎片），非语音簇（音乐/噪声）1141.6 s。
- **默认策略：全部保留**（只删头尾 + 内部长静音，见 §7.2）。抽样 11 段做 SenseVoice 转写 + 字符率判定，命中候选删除 **2 段 / 13.19 s**（高置信非讲课：非主讲 + ≥5 s + 字符率 <0.5 字/s）：

| 2 | 521.0–526.9 | 5.9 s | 非主讲 S2 | 啊原。 | **0.34** | **候选删除**（非主讲+≥5 s+字符率<0.5） |

## 10. 推荐参数与预设

```yaml
preset_standard:                    # 默认（单人讲课、源基本干净）
  decode: {ar: 16000, channels: 1, format: f32}
  denoise: "highpass=f=80,afftdn=nr=12:nf=-30:tn=1"
  vad:
    engine: silero_onnx             # 32ms 窗，投影到 10ms 帧
    threshold: 0.5
    min_silence_s: 0.3              # 合并 <0.3s 空隙
    min_speech_s: 0.25
    continuous_s: 3.0               # ≥3s 为连续说话段，<3s 为碎片（不参与电平/保守删除）
  trim:
    head_tail: "首个/末个 ≥3s 连续段 ±0.3s"   # 必须先用 120s ASR 字符率定讲课边界！
    internal_pause_min_s: 3.0
    guard_s: 0.25
  normalize:
    target_asl_dbfs: -20.0
    asl: "P.56 思路：20ms 窗/10ms 跳；只取连续段语音帧；L=L-15dB 迭代至 <0.01dB"
    variant: v2
    win_s: 20; hop_s: 5
    clamp_db: 3                     # wlx 这类内部波动 >±3 的文件放宽到 6
    max_rate_db_s: 1.5
    crossfade_ms: 20
    smooth_block_s: 1.0
  limiter:
    type: alimiter                  # attack 5ms / release 50ms / level=0
    ceiling_dbfs: -2.0              # 采样峰；生产建议真峰值限幅 ceiling -2.5~-3.0
    true_peak_check: ebur128(peak=true) + 回读下调重做
    target_tp_dbtp: -1.0
  head_boundary_rule:               # 生产必须
    window_s: 120
    cps_speech_threshold: 1.5       # 字/秒
    confirm_windows: 2
preset_noisy_source:                # 噪声明显时（需 A/B 复核）
  denoise: "aresample=48000,highpass=f=80,arnndn=m=sh.rnnn,aresample=16000"
  normalize: 同 preset_standard
```

## 12. 局限与后续

1. **ASL 是自研简化**（迭代门限法），非标准 P.56 认证实现；跨文件一致性依赖同一口径，不能与第三方 ASL 数值直接比较。建议生产固定该实现并写进规范。
2. **"连续段 ≥3 s"口径丢掉大量语音**：本批碎片合计 995–2215 s/文件（约 40% 语音帧），电平估计只用连续段，因此对"碎片里的轻声/插话"不敏感；若生产需要更稳的电平，可把口径放宽到"≥1.5 s"并重测（不影响本结论方向）。
3. **5 min 窗口只有 10–28 个样本**，p5/p95 是粗估；V2 的 C=3 dB 在 wlx 上不满足要求（需 6 dB），说明“±3 dB 限制”不是普适值，生产应按文件内波动自适应选 C（3 或 6），并在报告里留痕。
4. **头边界语义精度**（§7.2）：VAD-only 已切掉 xes 片头 7–480 s 音乐中的绝大部分（作为内部长静音），但 clean 开头仍残留 ~31 s 音乐；已给 120 s ASR 字符率方案，本次未重跑（修复后 xes clean 时长会再少 ~31 s）。
5. **真峰值**：xfzx V2 残余 -0.90 dBTP（超 0.1 dB），生产用真峰值限幅/ceiling -2.5~-3 可消除；xfzx 同时是"极安静源"（ASL -41.5，+21.5 dB 增益）——**底噪被同比抬高 21.5 dB**（降噪后底噪仍 ~-60 dBFS 量级），听感上会比原始"更吵"，建议对这类源先做 arnndn/DFN 降噪再归一化，或允许 T 降到 -21~-22 dBFS 以少放大 1–2 dB（需产品确认统一电平 vs 底噪的取舍）。
6. **未做主观听测**：A/B 片段（3 组 20 s）供人工抽检；客观指标显示无削波、无泵动，但 xfzx/lxg1 的强限幅段建议优先试听。
7. V3 仅做了 xes 官方 diarization 与 10 min 片段验证，结论"默认关闭"；若未来有真正的多人课堂数据，需重新评估 diarization 稳定性与最小簇时长阈值。
