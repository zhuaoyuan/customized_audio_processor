## 4. 方法

1. **元数据/解码**：`ffprobe -show_format -show_streams`；`ffmpeg -vn -ac 1 -ar 16000 -c:a pcm_f32le` → `work/scan/wav/<短名>.wav`（float32 单声道 16 kHz，供 VAD/ASR/diar 复用）。
2. **响度**：`ffmpeg -af ebur128=peak=true -f null -`，解析 Integrated LUFS、LRA、True Peak、门限与 LRA low/high；f00 用修复副本，其余用原始 m4a。
3. **VAD**：Silero VAD v6 ONNX（`faster_whisper/assets/silero_vad_v6.onnx`，onnxruntime 批量推理），threshold=0.5、min_speech=250 ms、min_silence=300 ms、speech_pad=100 ms。（未用 sherpa-onnx `SileroVadModelConfig`：本机可用模型是 v5/v6 的 h/c 状态接口，与 sherpa-onnx 的 v4 `state` 接口不匹配。）
4. **语音电平**：25 ms 窗 / 10 ms 跳 RMS dBFS；帧中心落在 VAD 语音段内即语音帧；**ASL = 10·log10(mean(10^(帧dB/10)))**（ITU-T P.56 活跃语音电平思路），另给语音帧 p10/p50/p90、噪声底（最安静 10% 帧能量均值）、SNR 代理 = ASL − 噪声底。
5. **5 分钟窗口**：互不重叠 300 s 窗，窗内语音 ≥30 s 才统计 ASL，取各窗 ASL 的 p5/p50/p95。
6. **非语音结构**：头可裁 = 第一段 VAD 语音起点（粗筛）+ ASR 复核（30 s 分块、连续 90 s ≥60 字）；尾同理；内部非语音 = 相邻 VAD 语音段间隔 ≥3 s 的段数/总时长/最长值。
7. **ASR**：sherpa-onnx SenseVoiceSmall int8（`work/bench/models/sensevoice`），8 线程、`language=zh`、`use_itn=True`。60 s 正文样本窗从 VAD 段滑动（步长 10 s、避开片头 5%）取语音覆盖最大者；字/秒 = 有效字符（汉字+字母数字，不含标点空格）/ 窗长。片头复核用 30 s 分块转写。
8. **说话人**：sherpa-onnx `OfflineSpeakerDiarization`（pyannote segmentation-3.0 + 3D-Speaker CAM++ zh），8 线程、自动聚类 threshold=0.5、min_duration_on=0.3 s / off=0.5 s；每文件取正文 10 分钟（起点 = VAD 首语音 + 60 s，且不越过片尾 20 s）。因阈值 0.5 会明显过聚类（原始 5~44 簇），再用 CAM++ embedding 的簇质心余弦 >0.70 做同人合并；**有效讲话人** = 合并后占语音 ≥5% 的簇数（排除碎片/音乐误判）。

## 5. f00 容器损坏与修复（实测）

`0_20140227-丁耘 西方哲学(...)_normal..m4a` 直接解码会从第一帧起报 AAC 解析错误（`Reserved bit set` / `Number of bands ... exceeds limit` / `channel element ... is not allocated`），拿不到任何音频。排查与修复：

- mdat 数据本身完好，`stsz` 样本大小之和 = mdat payload 字节数（73134337 B，完全相等）；
- **`stco` 的 70 个 chunk 偏移整体比实际 mdat 起点小 22118 B**（首 chunk 381996 vs mdat payload 404114），即 moov 内插入 `udta`（22216 B）后未更新 stco，导致每个样本从错误位置读取；帧起始 3 bit 元素 ID 呈均匀随机分布（好文件 100% 为 CPE），单帧解码成功率 0/40；
- 修复：仅把 stco 全部 +22118（副本 `work/scan/f00_fixed.m4a`，**`data/` 未改动**，`patch_f00.py` 可复现），解码错误数降为 **0**，完整解出 50.79 min；ASR 文本通顺（“这个有同学来认领啊…”），确认内容正确。
- 修复后该文件仍异常安静（ASL −39.8 dBFS、3 kHz 以上能量很少），说明源本身电平极低，不是修复导致。

## 6. 局限

- **⚠ VAD 的 first_speech 不可信（实测反例）**：`f24` 的 3.6 s 是片头音乐误触发（0–480 s ASR 无字，480 s 起真实讲课）；`f06`/`f20` 的 ~121 s 漏掉了 90–121 s 的轻声讲课；`f05` 的 0.2 s 是噪声。**裁剪实现必须以 ASR 有字为准**：本报告 §2.3 的 ASR 列 = 30 s 分块“本块 ≥10 字且后 3 块 ≥60 字”的首个时刻，精度 ±30 s；f24 尾部 4613 s 之后 60 s 无字（可裁）。
- **ASR 有字 ≠ 授课**：`f00` 0–90 s 有字但是课前闲聊（“怎么样他们问问怎么样…”），90 s 才进入课程介绍；这类片段用“字符率”判不出来，需要看内容（本报告已人工标注）。
- VAD 对音乐/噪声段可能误判，头尾裁剪秒数应视为“提示值 + ASR 复核后的值”，不宜直接硬编码。
- **ASL 未做 P.56 活动因子归一**：这里是语音帧能量均值，跨文件口径一致，绝对值不宜直接当标准 ASL。
- **LUFS−ASL 差小是这批数据的特性**（语音 66–85%）；语音占比低、音乐多的素材会明显分离，不能外推。
- **ASR 仅 60 s 抽样**：字/秒是局部值；首两句可能从句子中间开始；片头复核按 30 s 分块，边界精度 ±30 s。
- **diarization 是 10 分钟抽样**：人数是抽样窗内结果；阈值 0.5 会过聚类（原始簇 5~44 个），已用 embedding 余弦 >0.70 合并，但合并阈值本身是经验值；不能当全片说话人数。f24 的抽样窗落在讲课前音乐段，其“非主讲”主要是音乐/前奏。
- **f00 为修复后解码**：只改容器索引，源文件容器仍异常（32 kHz/193 kbps）；其响度/频谱只代表解码出的音频。
- 解码统一 16 kHz 单声道，8 kHz 以上信息丢失；True Peak 在解码/重采样后由 ffmpeg 测量，与原始采样点真峰值可能有 ±0.x dB 差异。
