## 1. 需求对齐与任务拆解

### 1.1 需求 → 技术任务

| 需求 | 子任务 | 技术 | 关键参数（默认） |
|---|---|---|---|
| ① 降噪 | 稳态噪声抑制 | `highpass=f=80, afftdn=nr=12:nf=-30:tn=1`；可选 `arnndn`(RNNoise) / GTCRN / DeepFilterNet3 | nr 可调 8–20 |
| ② 去非人声 | 头尾裁剪 + 内部长静音切除 | Silero VAD → 语音段；头尾取首末 ≥3 s 连续段；内部 ≥3 s 静音切除（两侧留 0.25 s） | pad 0.3 s / min_silence 3.0 s |
| ③ 音量稳定 | 语音活跃电平测量 + 增益 | 只统计 ≥3 s 连续语音段的语音帧；ASL = 语音帧能量均值；V1/V2/V3 + limiter −1 dBTP | T=−20 dBFS；跨文件 ±0.5 dB（实测 0.08）；窗口 5 min 半展宽 ≤ ±1.5 dB（V2 后实测 0.26–1.44）；真峰值 ≤−1 dBTP（f00 残 −0.90） |
| ④ 无关人声 | 保守过滤 | 默认保留；只删高置信：头尾 / 非主讲≥5 s 且 ASR 字符率<0.5 / VAD 判语音但 ASR 空 | 保守优先，可配 aggressive |
| ⑤a 转写 | 句级时间戳 + 发言人 | VAD 分段（0.5–30 s）→ 逐段 ASR → 句级 start/end；diarization 可选打标签 | 段合并阈值 0.3 s；speaker 仅在有稳定第二人时输出 |
| ⑤b 纠错 | 同音/专名修复 | 主题 + 课程热词 + 严格约束的 LLM 分块纠错；差异率校验，超限回退原文 | chunk 2,000–2,500 字；diff ≤12% |

### 1.2 关键定义（写进配置，避免"感觉"）

- **语音活跃电平（speech ASL）**：对 VAD 判为语音、且属于 ≥3 s 连续段的 25 ms 帧，计算帧能量平均值再转 dBFS。**排除**碎片（<3 s）、片头片尾、长静音。定义与 ITU-T P.56 的 active speech level 同思路，不直接用 EBU R128 LUFS（后者包含静音与音乐，跨文件不可比）。
- **连续说话段落 / 碎片**：VAD 段时长 ≥3 s 为连续段；<3 s 为碎片（需求③不计入、需求④按保守规则处理）。
- **长段非人声**：VAD 判非语音且 ≥3 s 的区间（含静音、音乐、环境噪声）。
- **无关人声**：非主讲说话人的语音段，且满足保守删除条件时才切除。

### 1.3 每个输入文件的产物

```
out/<件名>/
├── clean.m4a            # 干净音轨：降噪 + 裁剪 + 响度归一化（44.1k mono, 96 kbps）
├── clean_16k.flac       # 供 ASR/复查的 16k 无损（可选，省磁盘可关）
├── edit.json            # 裁剪区间、orig↔clean 时间映射、增益曲线统计、各项指标
├── transcript.json      # [{start,end,speaker,text_raw,text}]（clean 时间轴 + orig 时间）
├── transcript.md        # 人读稿：时间 + 发言人 + 修正后文本
├── transcript.srt       # 字幕（clean 时间轴，带发言人前缀）
├── corrections.json     # LLM 纠错明细（原→改 + 依据），供人工抽查
├── report.json          # 体检指标（LUFS/ASL/裁剪比例/段数/耗时）
└── log.txt              # 阶段日志
```

### 2.2 响度与语音电平（**需求③的直接依据**）

| id | LUFS(整段) | 语音 ASL dBFS | 底噪 dBFS | SNR dB | 语音占比 | 5 min 窗口波动(p5–p95) |
|---|---|---|---|---|---|---|
| f00 | **−42.7** | **−39.8** | −49.8 | **10.0** | 0.66 | 5.78 dB |
| f04 | −12.2 | −11.9 | −50.5 | 38.5 | 0.80 | 2.86 dB |
| f05 | −12.1 | −12.7 | −36.5 | 23.8 | 0.85 | 3.78 dB |
| f06 | −23.7 | −21.9 | −29.7 | **7.8** | 0.70 | 2.66 dB |
| f20 | −23.3 | −23.7 | −49.7 | 26.0 | 0.78 | **6.14 dB** |
| f24 | −10.1 | −10.1 | −28.2 | 18.1 | 0.68 | 4.00 dB |

**结论：**
1. **跨文件响度差达 29.7 dB（ASL）/ 32.6 dB（LUFS）**——"不管不同文件都输出稳定音量"是硬需求，必须逐文件归一化；LUFS 的离散度比 ASL 更大（因为 LUFS 含静音/音乐），**证实不能用 LUFS 做归一化目标**。
2. **文件内 5 min 窗口波动 2.7–6.1 dB（半展宽 1.5–4.1）**，6/6 文件都超过 ±1.5 dB——必须用 V2 慢变增益（§5.4 实测压到 0.26–1.44 dB），且要限制变化率避免泵动。
3. **极安静源**（f00：ASL −39.8、SNR 仅 10 dB）归一化要 **+19.8 dB**，底噪会从 −49.8 抬到 −30 dBFS，降噪必须同步加强；**已削顶源**（f04：真峰值 +5.6 dBFS）必须 limiter 兜底。

### 2.3 非语音结构与头尾边界

| id | 内部 ≥3 s 非语音 | VAD 首"语音" | **ASR 有字起点** | **头可裁** | **尾可裁** | 说明 |
|---|---|---|---|---|---|---|
| f00 | 291 s | 7.7 s | 0 s | 0 s | 0 s | 0–90 s 是课前闲聊（有字但非授课），**可再裁 90 s** |
| f04 | 182 s | 10.8 s | 0 s | 0 s | 0 s | 从讲课中途开始，无片头 |
| f05 | 138 s | 0.2 s | 30 s | 30 s | 0 s | VAD 0.2 s 是噪声；30 s 起点名 |
| f06 | **669 s（91 段）** | 121.6 s | 90 s | 90 s | 0 s | VAD 漏掉 90–121 s 轻声讲课 |
| f20 | 209 s | 121.0 s | 90 s | 90 s | 0 s | 同上 |
| f24 | 613 s（最长 170 s） | 3.6 s | **480 s** | **480 s** | **60 s** | VAD 的 3.6 s 是**音乐误触发** |

**关键教训（已写入计划 P2-T3）：VAD 单独判头尾不可信，段级 ASR 也不够，必须用 120 s 窗口聚合 ASR 字符率。** Silero VAD 会把片头音乐/掌声当成语音（f24 的 0–7 s、f06/f20 的 0–121 s 都是）；而段级字符率会被音乐上 ASR 的短幻觉词骗过（f24 的 59 s 处出现"觉的旁边他有"这类短句，字符率 >2）。实测 f24 的 120 s 窗口指标：

| 窗口 | 0–120 | 120–240 | 240–360 | 360–480 | **480–600** | 600–720 | … | 4440–4560 | 4560–4680 |
|---|---|---|---|---|---|---|---|---|---|
| VAD 语音占比 | 65% | 24% | 25% | 18% | 47% | 82% | 86–93% | 81% | 75% |
| ASR 字符/秒 | 0.42 | 0.25 | 0.24 | 0.47 | **2.26** | 3.73 | 3.7–4.5 | 2.62 | 1.49 |

→ 以 `chars/s ≥ 2.0` 为判据，边界稳定落在 **480 s / 4560 s**，与人工结论一致。**当前 PoC 的 VAD-only 裁剪虽然靠"内部长静音切除"切掉了 7–480 s 音乐的大部分，但会留下约 31 s 音乐在 clean 开头（VAD 把 7–48 s 部分音乐判成语音），clean 转写开头仍有"我去做饭"类幻觉——生产版必须换成窗口化 ASR 判据。**

### 2.5 输入健壮性

- **1/6 文件容器损坏**：f00 的 MP4 `moov` 中 `stco` 偏移整体缺 22,118 字节（`udta` 被插入后未更新），导致 ffmpeg 报 `Reserved bit set / Number of bands (41) exceeds limit (30)`、解码输出为空。**修复方式**：解析 box 树，把 `stco` 全部偏移 + delta 后另存；修复后 50.8 分钟音频正常解码。

## 3. 降噪（需求 ①）

### 3.1 结论（沿用 v1 实测，已在 6 文件上复核）

| 处理 | 底噪变化 | RTF | 语音段影响 | 结论 |
|---|---|---|---|---|
| `afftdn=nr=12` | +5.1 dB（−30.9→−36.0 dBFS） | **0.003**（78 min≈14 s） | 300–1000 Hz 几乎不动 | **默认** |
| `afftdn=nr=20` | +13.8 dB | 0.003 | 峰值顶到 0 dBFS，需限幅 | 重噪可选 |
| `arnndn`(RNNoise sh.rnnn) | +22.6 dB | 0.011 | 整体 −1.6 dB，需增益补偿 | 强降噪可选 |
| GTCRN ONNX | +38.4 dB | 0.049 | **吞字**（识别 195→161 字） | 不推荐前置 |

### 3.2 为什么不追求"更清晰"

本批源是 bilibili 转码的 **AAC 55–67 kbps**（其中一个 32 kHz/193 kbps），有效带宽约 14 kHz、4.5 kHz 以上接近编码噪声底。降噪只能"不恶化"，要让声音变亮需要带宽扩展/生成式美化（会引入 AI 味、且改变原声），不建议用于学术录音存档。

### 3.3 噪声类型与策略

- 本批录音底噪以**低频隆隆声 + 中高频宽带底噪**为主（v1 实测：0–300 Hz 能量集中，4 kHz 以上噪声很低），低切 + 温和频域降噪足够；
- 若某文件有空调/风机类**稳态噪声** → `afftdn` 提高 nr；若有**非稳态噪声**（人群、桌椅）→ VAD 裁剪比降噪更有效（§4）。

## 4. 裁剪与时间映射（需求 ②）

### 4.1 规则

1. **头尾**：用 120 s 窗口 ASR 字符率判据（§2.3）找首/末个讲课窗口，边界外各留 0.5 s；
2. **内部长段非人声**：VAD 判非语音且 ≥3 s 的区间，两侧各留 0.25 s 保护带后切除；
3. **碎片语音（<3 s）不切**（保守；它们是主讲人的短句/语气词）；
4. 输出紧凑时间轴 `clean.wav` + `edit.json` 的 `kept`（orig↔clean 映射），转写按 clean 时间轴输出，同时保留 orig 时间。

### 4.2 实测（6 文件，VAD-only 版 PoC）

| id | 裁剪比例 | 头裁剪 s | 尾裁剪 s | 内部切除 s | 语音保留率 |
|---|---|---|---|---|---|
| f00_xifang | 3.4% | 8.4 | 2.1 | 93.9 | 99.9% |
| f04_lxg4 | 2.8% | 38.9 | 4.4 | 186.6 | 99.7% |
| f05_wlx | 2.3% | 3.2 | 3.8 | 136.2 | 99.9% |
| f06_ly | 12.0% | 146.2 | 27.2 | 553.5 | 99.4% |
| f20_lxg1 | 6.0% | 141.9 | 5.1 | 220.9 | 99.8% |
| f24_xes | 17.1% | 7.3 | 27.0 | 763.2 | 99.7% |

- **语音保留率 99.4–99.9%**：内部静音切除没有伤到连续语音；
- **内部长静音切除非常有效**：f24 切掉 763 s，其中绝大部分是片头 7–480 s 的音乐与长停顿（clean 总长 3875.8 s，−17.1%）；
- **但头尾边界仍不准**：f24 的 `head_trim` 只有 7.3 s，靠内部切除才把音乐切掉，**clean 开头仍残留约 31 s 音乐**（转写里还有"我去做饭"）；f20 头切 141.9 s，而 ASR 复核真实讲课起点是 90 s，**多切了约 52 s 讲课内容**。→ 生产必须改用 120 s 窗口 ASR 判据（§2.3 / 计划 P2-T3），预期再减少 30–50 s 误切/残留；
- 内部切除量差异大（94–763 s），取决于主讲人停顿习惯，符合预期。

### 4.3 时间映射

- `edit.json.kept = [[orig_start, orig_end, clean_start, clean_end], …]`；
- `orig_to_clean(t)` / `clean_to_orig(t)` 用二分查找 + 线性插值，往返误差 <1 ms；
- 转写 `transcript.json` 每条同时给 `start/end`（clean）与 `orig_start/orig_end`（原始），SRT 用 clean 时间轴（与交付音频对齐），需要原始时间时查 JSON。

## 5. 音量稳定化（需求 ③）

### 5.1 为什么不能直接用 `loudnorm`/LUFS

| 证据 | 数值 | 结论 |
|---|---|---|
| 6 文件整段 LUFS | −42.7 ～ −10.1（**差 32.6 dB**） | 跨文件差异巨大 |
| 6 文件语音 ASL | −39.8 ～ −10.1（**差 29.7 dB**） | 需要逐文件归一化 |
| LUFS 与 ASL 的差 | 本批 −2.9 ～ +0.6 dB（语音占比 66–85% 时二者接近） | **但这只是本批特征**：LUFS 含静音/音乐，换一批语音占比低的文件就会偏离；且它无法区分片头/长静音 |
| 文件内 5 min 窗口 ASL 波动 | 2.7–6.1 dB | 单靠整段一个数不够，要看窗口 |

所以采用：**只统计"连续语音段"的语音帧，算 ASL（active speech level），再逐文件施加增益**；窗口波动超限时才加慢变增益。目标口径是 ASL，不是 LUFS（`loudnorm` 的 −16 LUFS 输出在 6 个文件上会因语音占比不同而产生 2–3 dB 的实际人声差异）。

### 5.2 目标与验收口径（锁定）

| 项 | 值 |
|---|---|
| 目标语音电平 T | **−20.0 dBFS ASL**（= 语音帧能量均值；不是 LUFS） |
| 跨文件一致性 | 处理后 ASL 与 T 偏差 **≤ ±0.5 dB** |
| 文件内波动 | 5 min 窗口 ASL 的 **半展宽 (p95−p5)/2 ≤ ±1.5 dB**（V2 实测 0.26–1.44，wlx 需 C=6） |
| 真峰值 | ≤ **−1.0 dBTP**（limiter 兜底） |
| 增益上限 | +24 dB（防止对极安静源过度放大底噪）；低于 −24 dB 截断 |

### 5.3 三个变体（f24 整片实测）

| 变体 | 说明 | 输出 ASL | 增益范围 | 最大增益变化率 | LRA 变化 | 结论 |
|---|---|---|---|---|---|---|
| **V1 静态** | 整文件一个 gain | −19.999 | −7.47（恒定） | 0 dB/s | 10.1（原 10.5） | **默认**：无伪影、最简单 |
| **V2 静态+慢变** | 20 s 窗/hop 5 s、clamp ±3 dB、速率 ≤1.5 dB/s | −19.998 | −10.47 ～ −4.47（6 dB 摆幅） | 0.64 dB/s | **8.5**（降 1.6） | 能把波动压一点，但有泵动风险，**按需启用** |
| **V3 按说话人** | diarization 分组后每组归一 | −19.999 | −7.39（退化为 V1） | 0 | 10.1 | 单主讲文件无收益；**pilot 中 diar 裂成 27 簇时会出现 ±5 dB 跳变 → 默认关闭** |

### 5.4 跨文件验证（6 文件整片实测，最终版）

> "窗口波动"= 5 min 窗口 ASL 的 p5–p95 **半展宽** = (p95−p5)/2，下同。

| id | 源 ASL | 静态增益 | V1 输出 | V1 半展宽 | **V2 输出** | **V2 半展宽** | V2 增益范围 | 最大速率 | 限幅触发 | 真峰值 |
|---|---|---|---|---|---|---|---|---|---|---|
| f00_xifang | −41.5 | **+21.5** | −20.08 | 1.94 | −20.02 | **0.72** | 18.5～24.5 | 0.82 | 1.08% | **−0.90** ⚠ |
| f20_lxg1 | −23.2 | +3.2 | −20.12 | 2.29 | −20.08 | **0.95** | 0.2～6.2 | 0.63 | 2.64% | −1.30 |
| f24_xes | −10.1 | −9.9 | −20.00 | 2.02 | −20.00 | **0.33** | −12.9～−6.9 | 0.63 | 0% | −3.30 |
| f04_lxg4 | −11.0 | −9.0 | −20.00 | 1.50 | −20.00 | **0.33** | −12.0～−6.0 | 0.64 | 0% | −1.90 |
| f05_wlx | −11.2 | −8.8 | −20.00 | 4.12 | −20.00 | **1.44** | −12.8～−2.8（**C=6**） | 0.99 | 0.02% | −1.20 |
| f06_ly | −22.5 | +2.5 | −20.00 | 1.61 | −20.00 | **0.26** | −0.5～5.5 | 0.61 | 0.09% | −1.20 |

- **跨文件输出 ASL 极差 = 0.12 dB（V1）/ 0.08 dB（V2）**——远优于 ±0.5 dB 目标；模拟"不同来源"（3 文件 × 5 段、人工加 −12～+6 dB）**15/15 回到 T±0.5，最大偏差 0.041 dB**；
- **文件内 5 min 窗口波动（半展宽）**：V1 有 **5/6 文件超 ±1.5 dB**（1.50–4.12）；**V2 后 6/6 全部 ≤1.44 dB**（0.26–1.44），**满足 ±1.5 dB 目标**；
- **唯一需要放宽 clamp 的文件是 wlx**（源内波动 8.25 dB）：clamp ±3 时残余 2.24 dB，放宽到 **±6 dB** 后 1.44 dB（变化率仍 0.99 dB/s）；
- **真峰值**：首轮样本峰限幅实测最高 **+0.80 dBTP**（不达标）；改为"回读真峰值→下调 ceiling 重做"后，5/6 ≤−1 dBTP，仅 f00（极安静源 +21.5 dB 增益、源含满刻度瞬态）残余 **−0.90 dBTP**（超 0.1 dB，需真峰值限幅器或 ceiling −3 dB 解决）；
- **伪影**：最大增益变化率 0.61–0.99 dB/s、限幅触发 0–2.64%、输出削波 **0**、LRA 从 9.5–14.1 LU 降到 7.8–9.3 LU。

> 结论：**"逐文件静态增益 + 受控慢变（V2）"是本需求的正解**；单靠 loudnorm/LUFS 或单靠静态增益都无法同时满足"跨文件一致"与"文件内波动受限"。

### 5.5 工程结论

1. **默认用 V2（静态增益 + 受控慢变）**：本批 6/6 文件都触发慢变层，输出 ASL −20.00～−20.08（极差 0.08 dB），5 min 半展宽全部 ≤1.44 dB；
2. **参数锁定**：窗 20 s / hop 5 s、clamp **默认 ±3 dB**、速率 ≤1.5 dB/s、20 ms 交叉淡化；若某文件源内波动 >6 dB（如 wlx 8.25 dB），**单独放宽 clamp 到 ±6 dB** 并在报告标 `high_drift`；
3. **±1.5 dB 的目标可以达成（V2 口径=半展宽）**：本批 V2 后 0.26–1.44 dB；单用 V1 不行（5/6 超限）。合同口径写明"5 min 窗口 ASL 半展宽 ≤1.5 dB"；
4. **limiter 必须真峰值**：`alimiter` 限的是采样峰，本批过采样真峰值比采样峰高 2.6–2.8 dB；生产用"4× 过采样测真峰 + 下调 ceiling 重做"，ceiling 设 −2.5～−3.0 dBFS，并对 5/6 之外的文件（f00）单独复测；
5. **极安静源（f00）要先降噪再放大**：+21.5 dB 增益把底噪从 −49.8 抬到约 −28 dBFS，SNR 仅 10 dB，听感必须抽检；极端情况允许 T 取 −21～−22 dB 或改用更强降噪（arnndn 48k 进出）；
6. **已削顶源（f04 真峰值 +5.7 dBTP）**：limiter 会触发（属正常），报告 `limiter_triggers`；xfzx/xes/lxg4 在增益前建议先峰值归一到 0 dBFS 以下，避免把削顶瞬态放大 20 dB。

## 6. 无关人声的保守处理（需求 ④）

### 6.1 策略（默认保守）

| 情况 | 处理 | 理由 |
|---|---|---|
| 头/尾非讲课（音乐、掌声、寒暄） | **删除**（需求②已覆盖） | 与课程无关，且量大 |
| 非主讲说话人、≥5 s、ASR 字符率 <0.5 字/秒 | **删除**（记 `other_speaker_low_chars`） | 听不清的远场人声/杂音 |
| VAD 判语音但 ASR 输出为空/纯标点 | **删除**（记 `vad_speech_asr_empty`） | 音乐/噪声误触发 |
| 能转写出的其他人声（问答、讨论） | **保留**，转写标 `其他1/2` | 可能是课程内容（讨论课），宁留勿删 |
| 碎片语音（<3 s） | **保留** | 主讲人短句，删了会丢内容 |

### 6.2 实测依据

- **本批 6 文件全部是单人讲课**：f00/f20/f04 抽样经合并后主讲占比 99.1%/99.9%/98.8%；f24 抽样里"第二簇 268 s"落在讲课前音乐区（233–480 s），不是第二讲课人；f05 只有偶发学生提问（60 s ASR 样本里出现一次）；
- f24 整片 diar（v1）：主讲人 70.3%，**非主讲真人语音仅 79.5 s（1.7%）**，其中约 30 s 还是主讲人被过分割的短句；
- 因此本批"无关人声"几乎没有，**删除收益≈0，激进策略反而会误删**；
- 反过来，**过分割是主要风险**（f00 原始 9 簇、f24 44 簇 → 合并后 1 人），所以 diarization 只在抽样确认有第二人时才启用，且只用于标注、不用于删除有内容的语音。

### 6.3 可配置

`configs/default.yaml`：
```yaml
unrelated_speech:
  mode: conservative        # conservative | off | aggressive
  max_chars_per_sec: 0.5    # 低于此视为无内容
  min_duration_s: 5.0
  keep_fragments: true
```
`aggressive`（需人工确认）：额外删除所有非主讲说话人段——不建议对讨论课使用。

## 7. 时间戳转写与发言人（需求 ⑤a）

### 7.1 方案

```
clean 16k ──Silero VAD──► 语音段（0.5–30 s；>30 s 均分）
        ──逐段 SenseVoice──► 文本 + 句级 start/end（clean 时间轴）
        ──（可选）diar 抽样/全量──► speaker 标签
        ──映射──► orig_start/orig_end
```

- 逐段解码复用同一个 recognizer 实例（加载 1–3 s，只做一次）；
- 纯标点/空文本段丢弃但保留时间（用于边界判定）；
- **禁止**"整段 30 s 分块 + 字符比例估时间"（v1 已证明误差可达数十秒）。

### 7.2 实测（f24 整片，clean 时间轴 64.6 min / 原始 77.9 min）

| 指标 | 值（clean 轴） | 对照：原始轴 |
|---|---|---|
| VAD 段数 | **785** | 928 |
| 转写字数（非标点） | **15,552** | 15,910 |
| 平均段长 / 中位段长 | 4.24 s / 3.09 s | 3.73 s / 2.83 s |
| 端到端耗时 | **115 s（RTF 0.0297）** | 234 s（RTF 0.050） |
| ASR 纯解码 RTF | **0.0259** | 0.0437 |
| 纯标点/无内容段 | 3 段 | 7 段 |
| 时间戳 | 句级（VAD 段边界，10 ms 精修） | 同 |

> 关键收益：**先裁剪再转写**，音频短了 17%，ASR 端到端从 234 s 降到 115 s（快一倍），且片头音乐导致的幻觉段大幅减少（clean 轴仍残留开头约 31 s 音乐 → "我去做饭"类；生产用窗口 ASR 边界可消除）。

### 7.3 时间戳精度（10 min 样本 600–1200 s，对照 faster-whisper 词级时间戳）

| 指标 | 段起点误差 | 段终点误差 |
|---|---|---|
| 匹配段数 | 133 | 133 |
| 中位（有符号） | **+0.22 s**（边界略晚于词起点） | **−0.47 s**（边界早于词终点） |
| P90 绝对误差 | **1.07 s** | **0.95 s** |
| 均值 / 标准差 | +0.23 / 0.58 s | −0.23 / 0.61 s |

结论：**中位误差 <0.5 s、P90 <1.5 s，达到字幕级要求**（验收线：中位 ≤0.5 s、P90 ≤1.5 s）。
注意这是与 faster-whisper 词边界的比较，参照本身有数十~数百 ms 抖动，且 VAD 在停顿处切句、词边界在词内，二者口径不同——1 s 的 P90 已包含这部分"口径差"。若要做逐字/卡拉 OK 级，需要 Paraformer 字级时间戳（成本更高）。

复现：`work/cost/ts_eval.py`（语料：`work/timeline/24_形而上学/transcript.json`）。

### 7.4 发言人标注

- 默认 `speaker="主讲"`（本批以单人讲课为主，避免臆造）；
- 抽样 diar（10 min × 3 段）发现稳定第二人（≥5 s 且 ≥3% 语音）才全量 diar；
- 全量 diar 结果按"总时长最大者为 主讲"，其余 `其他1/2`；
- 已知局限：短段 embedding 抖动会导致同一人被拆成多 id（v1 diar PoC 中 78 簇里 70 个是碎片），所以**只在有实质第二人时启用**，并在报告里标 `uncertain_speaker`。

### 7.5 输出

- `transcript.json`：机器可读，含 clean/orig 双时间、speaker、raw/corrected 文本、flags；
- `transcript.md`：`[mm:ss] 主讲：……`，人读/校对；
- `transcript.srt`：字幕，clean 时间轴，带发言人前缀；
- 时间戳误差验收：10 min 样本中位 ≤0.5 s、P90 ≤1.5 s（对照 faster-whisper 词级时间戳）。

## 8. 按主题修复错字（需求 ⑤b）

### 8.1 方法

```
transcript_raw ──按句切分/2,000–2,500 字一块──► LLM（主题+热词+严格约束）
        │                                                   │
        │                                       差异率/数字/句数校验
        │                                     ├─ 通过 → 用修正文本
        └─────────────────────────────────────┴─ 超限 → 回退原文并标记待人工
```

- **主题来源**：文件名 + 课程目录 + 转写前 300 字（一次本地拼接，不额外调用模型）；
- **热词**：`configs/hotwords/<课程>.txt`，由人工/首轮纠错结果沉淀（亚里士多德、形而上学、吴寿彭、李真、苗力田、耶格尔、陈康、安德罗尼科、物理学之后、潜能与现实、四因说……）；
- **严格约束**：只修同音/近音错字与专名；不改语序、不删口语重复、不润色；不确定保留；
- **校验**（防幻觉改写）：字符差异率 ≤12%、数字/页码/书名号数量不变、句数变化 ≤5%，否则该块回退原文并记入 `corrections.json` 的 `rejected`；
- **分块**：按句边界 2,000–2,500 字，无重叠（句边界切分已足够）；system prompt 固定以命中前缀缓存。

### 8.2 本机实测（4,200 字样例，deepseek-flash）

| 指标 | 值 |
|---|---|
| 原文/修正后字数 | 4,200 → 4,209 |
| 修改处数 | **63**（按条目 35 类） |
| 专名修复 | 亚里士多德系列 8、形而上学系列 13、人名 15（**吴寿彭**6、**李真**4、**苗力田**、**耶格尔=Jaeger**、**陈康**、毕达哥拉斯）、书名/术语 12（原著选读、工具论、牛津修订本、范畴篇、潜能与现实、质料在先…） |
| 过度修改 | 9 处"犹豫后改"（如"做不下来→坐不下来""夜望过去→一眼望过去""大二法卷→大阿尔法卷"），抽查均属合理；未发现改写句子 |
| 保留未改 | 不确定项（"神密大师""罗卜本/Loeb""北答卷/德查卷"等）如实保留，未臆造 |
| 风险 | 模型会依赖先验知识补全专名，**同一人名在不同课程可能被"纠正"成张冠李戴**；必须保留 `corrections.json` + 人工抽检，且对"删除/新增实体"类改动单独标记 |

> 质量评估：本样例中"原著选读""吴寿彭""李真""苗力田""耶格尔""陈康"等正是人工校对的痛点，LLM 全部改对，**单靠热词表做不到这种上下文推断**；同时它严格保留了数字、页码与断句，说明约束有效。

## 9. 批量架构（300+ 文件、持续新增）

### 9.1 流水线（阶段化、可断点续跑）

```
[0] 输入修复/解码   →  [1] VAD 分析   →  [2] 降噪(44.1k)  →  [3] 裁剪+mapping
        → [4] 响度归一化(+limiter) → [5] 编码 clean.m4a → [6] 分段 ASR
        → [7] (可选) diarization → [8] (可选) LLM 纠错 → [9] 导出 + 报告
```

每个阶段独立产物、独立状态；失败只重跑该阶段。SQLite 记录 `job(stage, status, error, attempts)`，支持 `--resume`。

### 9.2 并发与资源

- **默认单进程**：v1 实测 4 进程 × 4 线程比单进程 8 线程**慢 22%**（6 核机器），进程池不划算；
- 单进程内 ASR 用 8 线程（RTF 0.030）；ffmpeg 阶段是 I/O/CPU 混合，可与其他文件重叠 1 个；
- 可选 `--jobs 2` 仅用于掩盖 ffmpeg 等待，需实测确认不劣化；
- 显存：本方案默认不用 GPU（SenseVoice ONNX CPU；如启用 faster-whisper GPU 走 CT2）。

### 9.3 500 小时音频的时间估算（300 文件 × ~100 min）

| 阶段 | RTF（实测/估） | 500 h 音频耗时 |
|---|---|---|
| 解码 + 降噪 + 裁剪 + 响度 | 0.005–0.01 | 2.5–5 h |
| VAD 分析 | ~0.002 | 1 h |
| ASR（SenseVoice 8 线程） | 0.030 | **15 h** |
| 说话人分离（可选，全量） | 0.083 | 41 h |
| 说话人分离（抽样检测，10 min/文件） | — | ~4 h |
| LLM 纠错 | 云端并发，2500 并发上限 | **分钟级** |

→ **默认配置约 24 h/批**（可夜间跑）；启用全量分离约 63 h。磁盘：按文件即时清理中间 wav，最终产物 ~75 MB/文件（≈22 GB/300 文件）。

### 9.4 失败处理

- 解码失败（本批已遇到 1/6 的 MP4 `stco` 偏移损坏）→ 自动修复后重试，修不好进 `quarantine/` 并通知；
- 模型/文件缺失 → 任务挂起，不阻塞其他文件；
- 磁盘水位检查（<10 GB 停止取新任务）；
- 所有阶段异常写入 `log.txt` + `report.json`，Web UI 可一键重试。

> 关键观察：**98% 的 token 是缓存命中**（长上下文重复读取），单价 ¥0.02–0.04/M；token 体量大但费用极低，费用大头是输出（¥4/M）与未命中输入。
> 第二轮的三项单测（scan 6 文件体检 / audio-edit 6 文件渲染 / timeline 整片转写）各消耗 10–18M tokens，合计约 45M——这是"6 文件全链路实测"的真实价格：**不到 ¥5**。

### 10.3 全期开发预估

以两轮实测为标尺（147.2M tokens 交付：7 份调研 + 7 个 PoC + 主报告 + 计划），构建阶段代码量更大、迭代更多：

## 11. 风险与边界

| 风险 | 说明 | 缓解 |
|---|---|---|
| 源质量上限 | 55–67 kbps AAC，14 kHz 带宽，4.5 kHz 以上是编码噪声 | 降噪不"美化"；要变亮需带宽扩展（不建议） |
| 音量标准的主观性 | "人声平均音量"有客观定义（ASL），但听感还与频谱/动态有关 | 以 ASL 为准 + 人工试听 10 段校准；提供 `T` 可调 |
| 强行压平波动会"喘" | 慢变增益过大导致呼吸感 | 限制 ±3 dB、变化率上限、20 s 窗平滑；优先用静态增益 |
| 裁剪断句 | 静音切除可能切掉语气停顿 | 保留 0.25–0.3 s 保护带；阈值 ≥3 s 可调 |
| 无关人声误删 | 保守策略下误删风险低但仍存在 | 默认保留 + 抽检；`aggressive` 需人工确认 |
| 发言人标签不稳 | 短段 embedding 抖动 | 仅在有稳定第二人（≥5 s、≥3%）时标注；不确定标主讲 |
| LLM 过度修改/张冠李戴 | 先验知识可能补错专名 | 严格约束 + diff 校验 + `corrections.json` 人工抽检 |
| 输入损坏 | 本批 1/6 命中 MP4 `stco` 偏移损坏 | 自动修复（§2），修不好隔离并提示重下 |
| 法律/合规 | 公开平台下载的课程录音，用户已确认无需考虑隐私 | 仍建议仅自用、不二次分发 |

## 12. 验收标准与决策记录

### 12.1 验收标准（可量化）

| 项 | 标准 |
|---|---|
| 降噪 | 语音段 ASL 变化 ≤1 dB；非语音段能量下降 ≥5 dB；无削波 |
| 裁剪 | 语音段保留率 100%（VAD 段交集）；裁剪比例与人工试听 5 段一致 |
| 音量 | 6 文件处理后 speech ASL 极差 ≤1.0 dB（V2 实测 0.08 dB）；文件内 5 min 窗口半展宽 ≤ ±1.5 dB（V2 实测 0.26–1.44，wlx 需 C=6）；真峰值 ≤−1 dBTP（5/6 达标，f00 残 −0.90 需真峰限幅） |
| 转写 | 时间戳误差中位 ≤0.5 s、P90 ≤1.5 s（对照词级时间戳）；字数与 v1 基线比波动 ≤5% |
| 发言人 | 单主讲文件不出现多余发言人；有第二人时标签稳定（同人不拆、拆错率抽检 ≤10%） |
| 纠错 | 已知专名修正率 ≥80%；diff ≤12% 且无句子改写；`corrections.json` 完整 |
| 批处理 | 300 文件可断点续跑；单文件失败不影响批次；日志/报告齐全 |
| 性能 | 单文件（100 min）≤15 min（默认配置）；500 h 批次 ≤30 h |

### 12.2 已关闭的决策（工程默认值，无需用户再确认）

| 问题 | 决策 | 理由 |
|---|---|---|
| 应用形态 | **CLI + 本地 Web UI**（FastAPI + 原生前端，无 Node 构建链） | 用户已拍板；原生前端让 agent 可维护、零构建 |
| 规模/并发 | 单进程 + 8 线程；`--jobs` 可选 | 实测进程池更慢 |
| 产物 | clean.m4a（44.1k mono 96k）+ transcript.json/md/srt + corrections.json | 用户要文本+干净音频 |
| 隐私 | 不上传音频；LLM 只发文本 | 用户确认无隐私顾虑，但仍最小化上传 |
| 音量目标 | T = −20 dBFS ASL，跨文件 ±0.5 dB（实测 0.08），窗口半展宽 ±1.5 dB（V2 默认，实测 0.26–1.44）；wlx 单独 C=6 | 本批 6 文件实测（§5.4） |
| 裁剪阈值 | 头尾取首末 ≥3 s 段；内部 ≥3 s 静音 | 覆盖片头音乐/长停顿，同时保留语气停顿 |
| 说话人分离 | 默认关闭；抽样检测需要时才全量 | 本批非主讲人仅 1.7%，全量分离占 41 h 且会误切 |
| 纠错模型 | deepseek-flash（API key 由用户提供，环境变量） | 用户指定 |
