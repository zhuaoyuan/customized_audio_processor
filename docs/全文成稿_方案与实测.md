# 全文成稿（P10 方案）：整篇语境 + 口语转书面稿

> 状态：**已实现并接入 CLI**（`app/pipeline/compose.py` + `python -m app.cli compose`），
> 不改变现有 9 阶段流水线，不在 `run` 全链路里。实测对象：
> `0a7fa0ed_复旦哲学系丁耘_亚里士多德_物理学_05`（1:43:20，1,332 段）。
> 产物：`out/0a7fa0ed_复旦哲学系丁耘_亚里士多德_物理学_05/manuscript.md`。

## 1. 问题诊断（这批稿子为什么“还有很多问题”）

1. **纠错阶段实际没跑**：`out/jobs.db` 里 6 个 job 的 `correct` 均为
   `enabled=false, skipped=true, edits=0`；`corrections.json` 均为
   `{"total": 0, "items": []}`。看到的是 **SenseVoice 原始输出**，不是 P9 纠错后的文本。
   原因：运行时没有 `DEEPSEEK_API_KEY`（`correct.enabled` 需要 key 才生效）。
2. **上下文缺失**：原有纠错按 2,000–2,500 字分块，user prompt 只带热词表和开头 300 字；
   模型看不到整讲主题与专名出现规律，无法判断「无线→无限」「签能→潜能」这类同音词。
3. **口语化不在原设计范围内**：`configs/prompts/correct_system.txt` 明确禁止润色、合并句子，
   所以即使纠错生效，也不会把碎片句/口头禅变成通顺书面稿。

实测统计（该讲原始转写）：1,332 段，中位段长 16 字，**614 段 < 15 字**；
`呃` 232 次、`啊` 434 次、`这个这个` 160 次；`签能`/`潜证`/`前能`（应为潜能）、
`无线`（应为无限，10 次）、`定影`（应为定义，3 次）、`行而上学`/`刑商上学`（应为形而上学）等。

## 2. 方案：不是“一次塞给模型”，而是「通读 → 分块整理 → 边界合并」

单次把 3 万字讲稿塞给模型生成整稿不可行：输出长度受限、后半程容易漂移、局部错误无法回退。
采用三段式：

1. **通读全篇 → 课程档案**（1 次调用）：输入全讲逐句转写（带时间戳），输出
   标题/主题、8–15 条结构大纲、20–50 条术语表（正确写法 + 转写中真实出现的错写）、
   人物/书目、需注意的转写系统性问题。术语表里的 `variants` 会回查原文，虚构的直接丢弃。
2. **分块整理**（N 次调用）：按约 1,800 字段（不切段）分块，每块带
   课程档案 + 前文结尾 200 字 + 本块原文；要求合并碎片、去口头禅、按术语表纠错、
   保留例子/论证/数字/引文，输出以 `[mm:ss]` 开头的自然段（clean 音轨时间，对齐 `clean.m4a`；
   `manuscript.json` 另给每段 `orig_time` 原始轴时间）。
3. **合并与校验**：块间重叠 2 段，成稿后按块边界做字符级去重；
   每块校验长度比与时间戳（硬条件），增删数字/书名号进报告；整稿再查大纲覆盖与术语残留。

质量抽样：原文「这个无线呢我准备就放到下次讲了」→「无限我准备放到下次讲」；
「亚里斯德德完整的时间学说」→「亚里士多德完整的时间学说」；

碎片句（「那把这个。」「问题。」「推进到这个运动。」）合并为完整段落。
分块失败只会回退该块；本次最终成稿 0 回退，说明校验+重试路径可用。

## 4. 已知边界（必须人工抽检）

- **时间轴**：成稿 `[mm:ss]` 为 clean 轴（与处理后的 `clean.m4a` 一致）；原始视频时间查
  `manuscript.json` 每段的 `orig_time`（`transcript.md` 括号内 orig 时间同源）。
- 模型会**润色掉**它认为无意义的碎片；极少数无法辨认的转写可能被整句省略。
- 页码/Bekker 号（如 `201A10`、`2011A`）只按原文保留，未做学术核对；引文与专名需对照原音。
- 学生姓名（刘洋、王磊等）与课堂问答保留在原位；若要做“纯讲授成稿”，需要另一套 prompt。
- 无法自动证明“没有增补观点”，只能靠规则约束 + 人工抽检 + 与原文对照。

## 5. 已落地：`compose` 能力

- 模块：`app/pipeline/compose.py`；prompt：`configs/prompts/compose_system.txt`、
  `compose_analyze_system.txt`；配置：`configs/default.yaml` 的 `compose` 段。
- 产物：`manuscript.md`（成稿）、`manuscript.json`（段落/起止时间/来源块）、
  `compose_card.json`（课程档案）、`compose_report.json`（校验/回退/用量/成本）。
- 缓存：课程档案按 transcript hash 失效；分块结果按「档案 hash + 块文本 + 前文」缓存，
  改字后只重跑受影响块。
- CLI：

  ```powershell
  python -m app.cli compose <job_id> --dry-run      # 只看分块，不调 API
  python -m app.cli compose <job_id>                # 成稿（需 DEEPSEEK_API_KEY）
  python -m app.cli compose --all --limit 3         # 批量抽检
  python -m app.cli compose <job_id> --force        # 已存在也重做
  ```

- 并发：默认 **1**（实测 4 路长请求会被网关排队/超时）；配额允许时 `--concurrency 2/4`。
- 硬截止：urllib 单次 socket 超时可能被网关 keep-alive 拖住，模块用 daemon 线程 +
  queue 加了 `timeout + 30 s` 的总时限，超时即重试/回退，避免整篇被一个请求卡死。
- 校验：每块长度比、时间戳合法性/单调为硬条件；增删数字、丢书名号进报告（Bekker 页码常被
  规范化，不因数字差异整块回退）；失败重试一次，仍失败只回退该块（机械去语气词）并标 `fallback`。
- 成本：按本讲 ¥0.58 估算，300 文件约 ¥175；批量前先 `--limit 3` 抽检。
- 测试：`tests/test_compose.py` 18 项；全量 **476 passed**。

## 6. 当前风格与可选方向

- 当前保留课堂问答（学生提问、老师回应）并整理成书面表达，属于「完整课堂稿」。
- 若要做「纯讲授成稿」：另写一套 system prompt，删除问答/课堂管理段；块边界与校验可复用。
- 若只关心错字（不做润色）：仍用 `correct`，成本更低（P9 实测 ≈¥0.38/文件）。
